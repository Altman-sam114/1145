# v5.13 / 单选陆空作战射程椭圆

## 版本号与版本分配依据

- 版本号：v5.13。
- 分配依据：当前 main / origin/main 的最新实现提交为 v5.12「选中单位武器就绪刻度」（288f3c944c04d12f42c49f57284f429561d2bf81）。本轮仍属于 v5 触屏战斗识别阶段，只增加一个单选状态下的只读范围可视化，不改变攻击规则，因此递增一个小版本。
- 参考对象固定为百度百科 lemma 4042982 对应的 Noble Master Games《沙漠风暴 Desert Stormfront》，不是其他同名作品：
  https://baike.baidu.com/item/%E6%B2%99%E6%BC%A0%E9%A3%8E%E6%9A%B4Desert%20Stormfront/4042982

## 背景

当前原型已有：

- selectionNode 选择椭圆、v5.12 四段 Weapon readiness 刻度、实体旗标、六格耐久塔、FOCUS / ATK 和攻击意图线；
- Battleship / Coastal Battery 使用 navalGunRangeNode 的海军炮射程椭圆；
- SAM Site / AA Truck 使用 airDefenseThreatCoverageNode 的红色防空威胁圈；
- Mechanic 使用 repairCoverageNode，Carrier / 高价值舰艇使用护航或 guard anchor 覆盖圈；
- 所有这些节点均属于 GameEntity 实体树，并随实体镜像、移动、战争迷雾、死亡和重开生命周期处理。

单选 Blue Humvee、Tank、Artillery、Helicopter 或 Fighter 时，玩家仍缺少与海军炮圈同层级的“该单位实际陆空武器射程”反馈。需要补一个克制的等距友好射程椭圆，让玩家在地图上判断可攻击区域；它必须是纯视觉提示，不能成为新的目标合法性或攻击状态来源。

## 本轮目标

1. 为每个 GameEntity 预创建一个独立的陆空作战射程椭圆节点（建议命名 landAirCombatRangeNode 或同等清晰名称），并把它挂在该实体的 node 子树内。节点在 configureEntityNode(_:) 时创建一次、path 固定一次，不能在 updateHUD、refreshSelection 或每帧刷新中重复 addChild、重建 path 或创建临时 world 节点。
2. 只有以下条件同时满足时显示该椭圆：
   - 当前正好单选一个实体；多选、空选择、选择集合包含死亡或无效实体时不显示；
   - 实体 faction 为 player（Blue）、存活、operational，且 entity.node 当前可见；
   - entity.kind 不是结构，domain 为 land 或 air，kind.damage > 0；
   - 实体不是 AA Truck、SAM Site 或 Mechanic。AA Truck 继续只显示既有防空威胁圈；SAM Site 继续只显示既有防空威胁圈；Mechanic 继续只显示维修覆盖圈。结构、施工中实体和无伤害单位不显示通用作战射程。
   - 当前没有 pending 建造、rally、support 或 attack-move 状态（pendingConstructionKind、isSettingRallyPoint、pendingSupportPower、isSettingAttackMove 等现有状态均应使新椭圆隐藏）。
3. 椭圆尺寸必须使用对应 EntityKind 的既有 attackRange，只读现有静态数值，不新增或复制射程字段。可以沿现有 configureNavalGunRangeNode 的等距处理，采用完整水平轴、压缩垂直轴的 ellipseIn 几何；尺寸、线宽、透明填充和颜色应克制，保证小型 Fighter / Helicopter / Humvee 的模型、旗标、耐久塔和 v5.12 readiness 刻度仍清楚。
4. 陆空椭圆应使用与海军炮圈可区分的冷色或中性战术色（例如低 alpha 青蓝 / 绿色描边），不能变成红色防空威胁圈，也不能覆盖或改色现有 navalGunRangeNode。射程圈的中心和变换必须是实体本地坐标，随 entity.node 移动、xScale 镜像和相机缩放自然变化。
5. 显示判断应集中在一个只读 helper（例如 shouldShowLandAirCombatRange(for:)），由 refreshSelection() 和每帧现有视觉刷新路径共同维护；取消选择、切换到建筑 / Mechanic / pending、死亡、迷雾隐藏、实体销毁和重新开始 skirmish 后，所有新节点必须隐藏且不得残留上一选择颜色。
6. 不改变任何 HUD 文案、面板行、按钮、输入、目标环、FOCUS / ATK、Weapon readiness、耐久塔、旗杆旗标、来袭方向、命令意图、模型、粒子、伤害反馈或地图层级。玩家只通过地图上的新椭圆获得射程提示。

## 明确排除

- 不把新椭圆显示给敌方、未知敌方、neutral、死亡实体、未完工结构、隐藏实体或任何迷雾外位置；不得通过新节点泄露敌军或未侦测潜艇。
- 不为 AA Truck、SAM Site、Mechanic、HQ、Barracks、Airfield、Shipyard、Oil Derrick、Radar Outpost、Sonar Buoy、Guard Tower、Coastal Battery、Battleship、Submarine、Carrier 等实体增加本轮通用陆空椭圆。海军实体和 Coastal Battery 的既有 navalGunRangeNode 行为必须保持原样。
- 不复用 navalGunRangeNode 去覆盖陆空单位，不在同一实体上重复挂两个相同范围圈，不改写 configureNavalGunRangeNode 的海军判断、颜色、path、zPosition 或可见性。
- 不改变 canAttack、attackTarget、attackRange 数值、fire(attacker:target:)、updateCombat(dt:)、攻击冷却、伤害、目标选择、攻击站位、AI、经济、生产、维修、老兵、任务、胜负或重开规则。范围圈只读既有 EntityKind.attackRange。
- 不把射程圈当作目标合法性判断；玩家点按、迷雾、潜艇 revealedUntil / sonar、敌方已知规则和攻击范围校验继续走原有逻辑。
- 不新增文字、范围数字、HUD 行、进度条、按钮、页签、音频、贴图、外部依赖、随机动画、粒子、保存字段、测试专用状态或新的 capture 场景。
- 不修改 .github/workflows/ci-results.yml，不新增第 25 次 launch 或 PNG；复用现有 24 张云端截图探针。
- 不运行本地 Xcode build、本地 simulator、本地截图或本地玩法探针，除非人工另行明确要求。
- 不修改、覆盖、暂存或提交人工 DesertFrontline.xcodeproj/project.pbxproj Team ID 改动、未跟踪 md/unity分析/、构建产物、现有未提交 update_log.md 或其他无关工作树变化。

## 当前架构依据

- DesertFrontline/GameScene.swift 是当前事实核心。GameEntity 已有 selectionNode、weaponReadinessNode、navalGunRangeNode、sonarCoverageNode、escortCoverageNode、repairCoverageNode、carrierGuardAnchorCoverageNode、airDefenseThreatCoverageNode 等实体内节点。
- configureEntityNode(_:) 一次性构造实体模型、选择圈、v5.12 readiness、海军 / 防空 / 维修 / 护航覆盖节点和标签。新节点必须在该初始化阶段预创建并加入 entity.node；不能在 update loop 动态构造。
- refreshSelection() 根据 selectedIDs 切换 selectionNode、rally / coverage 节点，并刷新 command intent 与 FOCUS。新增 helper 应复用 selectedIDs，不建立第二套选择集合；单选判断必须以当前存活 selected entity 为准，避免 stale ID 让圈显示。
- updateHUD() 每帧刷新 selected、readiness、air-defense、incoming threat、command intent、FOCUS 和 selection info。新范围节点可在此处只读更新 hidden / alpha / 颜色，但不得每帧重建几何。
- shouldShowNavalGunRange(for:) 目前只允许玩家存活 operational 的 Battleship / Coastal Battery；该 helper 和 navalGunRangeNode 必须保持语义不变。configureAirDefenseThreatNodes(for:) 目前为 SAM Site / AA Truck 预创建红色防空威胁圈；不能把它改成通用陆空射程。
- entity.node.isHidden 是战争迷雾 / 隐身 / 实体可见性的最终父节点边界；新圈必须挂在实体树内并继承该边界，不能挂到 effectsLayer、focusFireMarkerNode 或其他 world-level 层。
- 实体镜像通过 entity.node.xScale（capture 或敌方模型可能为 -1）处理；椭圆应使用对称本地几何，不手动改世界坐标或建立另一套镜像节点。
- entity.kind.attackRange 是战斗系统现有静态射程；本轮只使用它来绘制，不改变 updateCombat 或目标合法性。kind.damage > 0、isOperational 和 isAlive 是通用显示资格，AA Truck / Mechanic 仍须显式排除。
- pendingConstructionKind、pendingSupportPower、isSettingRallyPoint、isSettingAttackMove 会让 HUD / 选择进入待处理模式。新圈在这些模式中隐藏，但不得清除选择、改变 pending 状态或修改现有海军 / 维修覆盖圈。

3. 在 GameEntity 增加一个预创建的 SKShapeNode（或等价单一实体节点），在 configureEntityNode(_:) 中按 entity.kind.attackRange 生成一次 isometric ellipse path。推荐使用完整水平轴、约 0.5–0.65 的垂直压缩比例，具体比例以当前地图视觉为准；不要把 ellipse 画成巨大圆盘或扩大 selectionNode。
4. 为新节点设置低 alpha 填充、清晰但克制的描边和低于模型 / 标签 / 旗标 / 耐久塔的实体内 zPosition。新节点默认 hidden；不得影响 selectionNode 的 lineWidth、v5.12 readiness tick 的位置和颜色。对小型单位可使用有限的线宽 / alpha clamp，但不得按每帧缩放或改变 path。
5. 新增 shouldShowLandAirCombatRange(for:)（或同等单一 helper），同时检查：
   - selectedIDs.count == 1 且当前 entity.id 被选中；
   - faction == .player、isAlive、isOperational、!entity.node.isHidden；
   - !kind.isStructure、kind.domain == .land 或 .air、kind.damage > 0；
   - kind != .aaTruck、kind != .samSite、kind != .mechanic；
   - pendingConstructionKind == nil、pendingSupportPower == nil、!isSettingRallyPoint、!isSettingAttackMove。
   需要时可再检查 selectionNode 未隐藏，但不得绕过父节点 fog 规则。
6. 在 refreshSelection() 和每帧现有视觉刷新路径中只更新新节点的 isHidden / alpha / strokeColor 等显示属性。每次刷新先对所有实体隐藏新圈并恢复默认颜色，再只打开唯一合法单选实体，防止从上一选择、上一阵营或上一帧残留。不要在 updateHUD 或 updateCombat 中 addChild、removeFromParent 或重建 path。
7. 保持现有可见性优先级：新圈应位于选择圈外、模型下方或低侧，不遮盖地面模型；不能盖住 v5.12 readiness ticks、旗杆 / 旗布、六格耐久塔、FOCUS / ATK、命中环、炮线、导弹、水柱、航迹、烟火、repair beam、escort / sonar / carrier guard 圈。若多个既有覆盖圈同屏，使用低 alpha 和稳定 zPosition，而不是移动既有节点或扩大边界。
8. 核对状态链路：玩家单选 Humvee / Tank / Artillery / Helicopter / Fighter 可见；多选同类或跨域单位隐藏；AA Truck、Mechanic、建筑、Battleship、Coastal Battery、Carrier、Submarine 保持各自现有圈；pending build / rally / support / AMOV 隐藏；敌军 / 未知目标 / fogged node 隐藏；死亡、cull、skirmish restart 后新节点无残留。所有新判断必须是只读展示，不写回 selectedIDs、attackTarget、attackTimer、hp 或任何战斗字段。

## 风险和禁止项

- 风险：attackRange 较大的 Tank / Artillery 或空军椭圆可能压过地貌、其他实体和海岸反馈。使用有限垂直压缩、低 alpha、稳定低 zPosition；不得缩放或移动模型、选择圈、旗标、耐久塔、FOCUS / ATK 或 HUD。
- 风险：把 AA Truck 当作普通 land combat 会与红色防空威胁圈混淆。必须保留显式 AA Truck 排除，SAM Site / Mechanic 也必须排除。
- 风险：只在 refreshSelection() 更新会在实体移动 / fog / pending 状态切换后残留；必须接入现有每帧视觉刷新入口，但只能刷新预创建节点属性。
- 风险：复用 navalGunRangeNode 可能让 Battleship / Coastal Battery 出现重复圈或改变海军颜色。新节点必须独立，navalGunRangeNode 的配置和 helper 不得被改写。
- 禁止为敌方、未知目标、潜艇隐身状态或 fog 外位置创建可见范围 cue；禁止把新节点放入 effectsLayer、focusFireMarkerNode 或其他独立 world 层。
- 禁止新增射程字段、攻击规则、目标分配、AI、输入、经济、生产、维修、任务、胜负、capture 状态、素材、外部依赖、workflow launch 或第 25 张截图。
- 禁止使用 reset / checkout 覆盖用户改动；禁止提交 project.pbxproj Team ID、md/unity分析/、构建产物、未提交 update_log.md 或其他 Agent / 用户改动。
