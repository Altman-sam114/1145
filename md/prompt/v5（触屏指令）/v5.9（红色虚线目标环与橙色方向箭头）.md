# v5.9 / 红色虚线目标环与橙色方向箭头

## 版本号与版本分配依据

- 版本号：`v5.9`。
- 分配依据：`v5.8` 已完成 Battleship 两档战损与合法反潜命中反馈，正式日志将“红色虚线目标环与橙色方向箭头”列为下一轮候选；本轮继续 v5 触屏指令阶段，参考 Noble Master Games《Desert Stormfront》官方截图中高辨识度的攻击目标语言，对现有共享直接攻击 marker 做一个范围有限、可由既有云端截图明确验收的视觉增量，因此顺序递增为 `v5.9`。

## 背景

- 参考对象固定为百度百科 lemma id `4042982` 对应的 Noble Master Games《沙漠风暴 Desert Stormfront》，不是其他同名作品。参考图的攻击目标以“红色虚线椭圆环 + 橙色 V 形下指 cue”快速区别于绿色选择圈和普通移动落点；本轮只借鉴这种信息层级，不复制原图、纹理或 UI 素材。
- 当前 `showAttackTargetMarker(...)` 已按目标 footprint 缩放，显示红色半透明实线椭圆、四角粗括号、中心点与 `ATK ...` 文本。它能确认攻击，但在陆海空模型、FOCUS 双环和红色攻击意图线同时存在时，粗括号与中心点较拥挤，也不够接近参考图的清晰目标语言。
- `issueDirectAttackOrder(...)` 是精确敌军点击、26pt 敌军触屏辅助与 `TGT` 循环共用的玩家攻击执行 helper；三条路径最后都调用同一个 `showAttackTargetMarker(...)`。因此本轮应只重绘该共享 marker，不在各入口重复创建视觉节点。
- 云端已有 `simulator-command-attack-target.png` 隔离展示持久 attack-target marker，`simulator-target-cycle.png` 展示真实 `issueCycleTargetOrder(...)` 后的持久 `ATK 2/3 ART`、FOCUS 与四条攻击意图线，`simulator-enemy-touch-assist.png` 展示真实辅助点击后的 `ATK TAP JET` 与空中目标组合。这三张图已经覆盖本轮视觉，无需新增重复的第 25 次 launch。

## 本轮目标

1. 将 `showAttackTargetMarker(...)` 的主轮廓改为红色虚线等距椭圆目标环：
   - 继续使用现有 footprint-aware `width` / `height` 范围，陆、海、空目标都能被环包围且不会因大型 footprint 无限放大。
   - 用椭圆 `CGPath` 的稳定 dash pattern 绘制真正断开的红色线段，而不是摆放随机短线或逐帧生成节点；建议红色主线宽约 2.6-3pt、dash 约 8-10 / gap 约 5-7，并可在其下增加一条略宽、低透明黑红底线以保证沙地与青色水面上的对比。
   - 可保留极淡的红色内填充以聚焦目标，但 alpha 必须低，不遮挡单位模型、血条、旗标或 FOCUS 八段耐久。
2. 在目标环上缘内侧增加橙色 / 琥珀色双 V 下指 cue：
   - 两个紧凑开放 V 均朝向环中心，形成明确“此处为攻击目标”的方向性，不表示单位移动朝向、弹道方向或侧翼规则。
   - V 的宽度、纵向间距和挂点随 marker 尺寸轻量缩放或 clamp，既能在 Fighter 等小目标上辨认，也不越出 Battleship 等大目标过远。
   - 使用深色低透明背线加亮橙前线，保证在沙地、道路、水面和红方模型上都可读；不得增加持续闪烁、旋转或每帧动画。
   - V 应位于环上缘内侧或紧贴上缘，避免上侵既有 `FOCUS n CODE HP%` 世界文字区。
3. 简化旧 marker 的视觉冲突：移除现有四角粗括号和中心红点，或将其降为不会与虚线环 / V 竞争的极弱细节；最终画面必须以“红色虚线环 + 橙色双 V”为第一识别信号。
4. 将 `ATK <label>` 文本移到环下方的稳定位置，继续显示 `ATK JET`、`ATK TAP JET`、`ATK 2/3 ART` 等现有字符串，不改变 label 生成规则；文字不得与上方 V、FOCUS 文本、目标血条或实体 label 重叠。
5. 保持现有普通动画与 capture 行为：普通攻击 marker 仍短时淡入、缩放、淡出并移除；`persistent: true` 仍只用于既有云端 capture。不得让普通玩法留下常驻节点或逐次攻击累积节点。
6. 直接点击、TGT、敌军触屏辅助三条路径继续复用 `showAttackTargetMarker(...)`，自动获得同一视觉；不得修改 `issueDirectAttackOrder(...)` 的命令字段、消息、攻击者过滤或返回值。
7. 不新增第 25 张截图，不改 `.github/workflows/ci-results.yml` 的既有二十四次 launch。使用三张既有截图做交叉验收：
   - `simulator-command-attack-target.png`：隔离核对红色虚线环、橙色双 V、下置 `ATK JET` 和空中目标无遮挡。
   - `simulator-target-cycle.png`：核对真实 `ATK 2/3 ART`、FOCUS、目标血条和四条红色攻击意图线的层级与间距。
   - `simulator-enemy-touch-assist.png`：核对缩远镜头下 `ATK TAP JET`、双 V、FOCUS 与 Fighter 模型仍清晰。

## 当前架构依据

- `showAttackTargetMarker(at:footprint:label:persistent:)` 位于 `GameScene.swift` 的 command marker helper 区，当前负责 footprint 尺寸、红色环 / 括号 / 中心点、`ATK` label 和 `presentCommandMarker(...)` 调用；本轮主要修改点应限制在该 helper。
- `presentCommandMarker(...)` 统一管理普通 marker 的短时淡入 / 缩放 / 淡出 / 删除，`persistent` 时仅冻结 capture 证据；本轮不得复制或绕过该生命周期。
- `issueDirectAttackOrder(...)` 在验证敌方存活、玩家已知和逐单位 `canAttack(...)` 后写入攻击命令，再调用 `showAttackTargetMarker(...)`；精确点击、`TGT` 和 touch assist 均复用它。
- `refreshCommandIntentVisuals(...)` / `updateCommandIntentMarker(...)` 只读当前命令状态，攻击目标使用红色虚线意图线；本轮 marker 重绘不应触及该链路。
- `focusFireMarkerNode` 位于 `effectsLayer` 且有效层级低于 command marker，显示共享目标的双环、`FOCUS n CODE HP%` 与八段血条；新的上缘 V 和下置 ATK 文本必须以该既有组合为布局约束。
- `prepareCIAirCaptureScene()` 的 `attack-target` 分支直接调用同一 marker 并传 `persistent: true`；`prepareCITargetCycleCaptureScene()` 与 `prepareCIEnemyTouchAssistCaptureScene()` 分别真实调用 TGT / touch-assist helper 并冻结同一 marker，不需要新增 capture-only 状态。
