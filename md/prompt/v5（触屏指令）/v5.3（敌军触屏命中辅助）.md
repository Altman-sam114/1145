# v5.3 / 敌军触屏命中辅助

## 版本号与版本分配依据

- 版本号：`v5.3`。
- 分配依据：v5.1 已提供视野内 `TGT` 循环集火，v5.2 已提供友军 26pt 屏幕尺度辅助选择和重叠循环；本轮沿用 v5 触屏指令阶段，补齐普通世界点击对缩远镜头下敌方小模型的直接攻击辅助，不扩展新的 HUD 动作或战斗规则。

## 背景

当前 `handleWorldTap(at:tapCount:)` 已按 pending 支援 / 建筑 / rally / attack-move、精确 `entity(at:)`、友军辅助选择、空地移动分流。精确敌军点击会调用 `issueDirectAttackOrder(...)`，但没有命中敌军原 footprint 时会先落入友军辅助选择或地面移动。空中小目标在缩远镜头下因此仍难以直接点中。v5.3 需要在精确实体与友军辅助之间加入受玩家认知和所选武器能力约束的敌军辅助命中，并继续复用唯一直接攻击执行链路。

## 目标

1. 普通世界点击的固定优先级为：pending 模式 > 精确实体 > 合法敌军 26pt 辅助 > 友军 26pt 辅助 > 空地移动 / 原有空选择处理。
2. 敌军辅助候选只包含存活、玩家已知，且至少能被一个当前选中、存活、玩家阵营、非结构、`isOperational`、有伤害的机动单位通过 `kind.canAttack(target.kind)` 攻击的敌军。
3. 敌军辅助半径使用 `max(target.kind.footprint * 0.95, 26 * cameraRig.xScale)`，保持约 26pt 屏幕最小触控范围；候选按点击点距离的 0.5 世界距离桶、再按 entity id 建立严格总序，只选择第一项且不循环。
4. 辅助命中成功必须调用既有 `issueDirectAttackOrder(on:units:...)`，并显示短时红色 `ATK TAP CODE` 世界反馈；选择、目标 HP、命令意图线和 Carrier guard release 等继续由既有攻击链路刷新。
5. 精确敌军仍无条件优先于辅助候选；精确点击不可攻击敌军时继续显示既有 `NO ATK` 拒绝反馈，不得转而攻击附近另一个可攻击敌军。精确己方的单击 / 双击、v5.2 友军辅助循环和空地移动保持原行为。
6. 新增 capture-only `enemy-touch-assist` 和 `simulator-enemy-touch-assist.png`，将 GitHub Actions simulator launch probe 从二十二次扩展为二十三次。

## 非目标

- 不新增 HUD 页签、按钮或动作，不改变 TACT 九动作与全局 26 动作。
- 不改变单位 footprint、射程、伤害、冷却、寻路、移动、AI、经济、生产、任务、胜负或 `TGT` 循环行为。
- 不扩大玩家对战争迷雾内敌军的认知，不暴露未侦测 Submarine，不改 `revealedUntil`、sonar 或 `isKnownToFaction(...)` 语义。
- 不为敌军辅助点击保存循环 cursor，不循环重叠敌军，不让辅助敌军抢占任何精确实体。
- 不新增外部依赖或素材，不修改签名 Team ID，不纳入 Unity 迁移报告，不做无关重构。

## 当前架构依据

- `GameScene.handleWorldTap(...)` 是普通世界点击的事实分流入口；pending 支援、施工、rally 和 attack-move 必须继续先于普通选择 / 攻击。
- `entity(at:)` 是精确实体命中入口，已过滤死亡实体、玩家未知敌军，并按 0.5 世界距离桶 + id 形成严格总序。
- `playerSelectionCandidates(at:)` / `selectPlayerEntity(...)` 已实现 v5.2 的 26pt 屏幕尺度友军候选和循环，本轮不得改变其候选、cursor 或反馈规则。
- `issueDirectAttackOrder(...)` 是地图直接攻击与 `TGT` 共用的唯一攻击执行 helper，集中维护 `canAttack` 过滤、互斥命令清理、Carrier guard 解绑、攻击 marker、选择面板、HUD 与消息。
- `isKnownToFaction(..., observer: .player)` 是敌方可知性边界；Submarine 还必须继续经过 `revealedUntil` / sonar 检测。
- CI capture 由 `DESERT_CI_CAPTURE_MODE=1`、`DESERT_CI_COMMAND_MARKER` 和 `prepareCICaptureScene()` 分流；workflow 独立启动、截图、PID 存活检查并把结果列入 manifest。

## 风险与禁止项

- 风险：世界半径必须乘 `cameraRig.xScale` 才保持屏幕尺度；把 26 当固定世界距离会在缩放时失真。
- 风险：用 `abs(distanceA - distanceB) < 0.5` 直接写 comparator 可能破坏严格弱序；必须先生成 0.5 距离桶，再用 id 打平。
- 风险：先跑友军辅助会在友敌贴身时吞掉合法敌军攻击；先跑敌军辅助又不得越过任何精确实体，因此分流位置必须严格遵守目标 1。
- 风险：仅检查目标可知而不检查所选 operational 作战单位的 `canAttack` 会把不可执行目标吞掉地面移动；候选阶段与执行阶段都必须保持合法性。
- 禁止绕过 `isKnownToFaction(...)`、潜艇侦测或 `issueDirectAttackOrder(...)` 直接写攻击状态。
- 禁止修改 v5.2 友军 cursor、`TGT` cursor、战斗数值、单位模型、地图、AI 或 HUD 动作数量。
- 禁止把 capture-only 坐标、镜头缩放、persistent marker 或状态写入普通启动路径。
- 禁止本地 build、simulator 或玩法探针；禁止提交 Team ID、Unity 报告、构建产物或无关格式化。
