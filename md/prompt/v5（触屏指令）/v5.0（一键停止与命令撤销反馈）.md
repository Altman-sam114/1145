# v5.0 / 一键停止与命令撤销反馈

## 版本号与分配依据

- 版本号：`v5.0`。
- `v4.99` 已完成陆、空、海三域持续受损状态和第十九个云端截图探针；本轮从连续视觉强化转入触屏命令易用性，作为新的交互阶段起点，因此递增到 `v5.0`。

## 背景

Noble Master 官方 Desert Stormfront press kit 将游戏定位为面向 casual / touch-screen players 的简化实时战略。官方截图中，选中单位后的 `Move / Patrol / Repair / Stop` 上下文命令集中、对比清楚。当前 Desert Frontline 已有 ARMY、控制组、HOLD、AMOV、RLY 和 HQ 等战术动作，也会用选中单位命令意图线显示 attack / attack-move / move / hold，但缺少在高密度战斗中快速撤销错误命令的统一入口。

## 本轮目标

1. 在 tactical 单排命令条新增高辨识度 `STOP` 动作，放在 HOLD 与 AMOV 邻近位置，不移除 G1 / G2 / RLY / HQ。
2. STOP 只对当前选中的、存活的玩家机动单位生效，并统一清理：
   - `destination`
   - `path`
   - `attackTarget`
   - `attackMoveDestination`
   - `holdPosition`
   - Helicopter / Fighter 的 Carrier guard anchor
3. 选中 Carrier 被 STOP 时，主动解除仍绑定到该 Carrier 的 guard wing anchor；未选中的 wing 保留自身当前位置 HOLD，不额外下达移动或攻击命令。
4. STOP 后保持原选择，立即刷新选择圈、HUD、战斗摘要和命令意图线。
5. STOP 按钮副标题显示当前选择中可撤销命令数，空选择或全 idle 时明确显示 idle，并通过颜色 / 明度区分可用状态。
6. 世界中显示短时 `STOP n` 确认标记；顶部消息同时给出停止数量和 Carrier guard release 组成反馈。
7. 新增 capture-only `stop-command` 场景和 `simulator-stop-command.png`，将云端 simulator launch probe 从十九次扩展到二十次。

## 非目标

- 不新增 Patrol、Repair 上下文按钮或键盘快捷键。
- 不改变移动、攻击、HOLD、AMOV、航母警戒站位、AI 调度、寻路、目标合法性或伤害算法。
- 不改变生产、经济、战争迷雾、任务、胜负、重开 skirmish 或单位模型。
- 不引入外部依赖或外部素材。
- 不触碰用户未提交的 Xcode Team ID 与 Unity 迁移分析报告。

## 当前架构依据

- `HudAction` / `HudPage.actions` 定义单排命令条动作与归属。
- `buttonColor(for:)`、`subtitle(for:)`、`refreshHudButtonStyles()` 和 `updateHUD()` 负责按钮动态状态。
- `handleHudAction(_:)` 是玩家 HUD 命令入口；`selectedMobilePlayerUnits()` 是选中玩家机动单位统一口径。
- `issueHoldPositionOrder(...)` 与 `issueFormationMove(...)` 已展示命令字段的互斥清理顺序。
- `carrierGuardAnchor(for:)`、`clearCarrierGuardAnchor(for:)` 和 `carrierGuardReleaseSuffix(for:)` 是 Carrier guard 有效性与反馈边界。
- `refreshCommandIntentVisuals(...)` 只读取 attack / attack-move / destination / path / hold；STOP 清理字段后应自然隐藏意图线。
- `prepareCICaptureScene()` 按 `DESERT_CI_COMMAND_MARKER` 分流 capture-only 场景，普通 App 不进入这些状态写入分支。

## 实现步骤

1. 给 `HudAction` 新增 STOP case、标题、tactical actions 排列、颜色、副标题和动态可用样式。
2. 新增小型 helper，统一判断一个玩家机动单位是否存在可撤销命令；按钮计数和执行筛选必须复用同一口径。
3. 新增 STOP 执行 helper：
   - 过滤当前选中的存活玩家机动单位。
   - 无选择时给出清楚提示；已有选择但全 idle 时提示无需撤销。
   - 在清理 Carrier HOLD 前快照其有效 bound guard wing，并与选中 wing 的有效 anchor 去重统计。
   - 清理本轮目标列出的六类状态；对未选中但绑定到被 STOP Carrier 的 wing 只清 anchor，不清其 ordinary HOLD。
   - 保持 `selectedIDs` 不变并刷新选择 / HUD。
4. 新增紧凑 STOP 世界 marker，包含高对比环、停止符号和 `STOP n`；普通玩法短动画，CI capture 可持久显示。
5. 新增 `prepareCIStopCommandCaptureScene()`：编排可辨识的陆、空、海玩家单位，在调用真实 STOP helper 前分别冻结 move / attack / AMOV / HOLD 和 Carrier guard 状态；调用后保留多选、清除所有意图线并显示持久 STOP marker。
6. workflow 增加第二十次 tactical / coast / `stop-command` 启动、PID 存活检查、PNG 清理与 manifest 条目。
7. 同步 `README.md`、`md/flow/flow.md`、`md/flow/flowchart.md` 和 `md/test/test.md`。

## 验收标准

- tactical 命令条完整显示 STOP，所有页签和原动作仍在单排内且无溢出。
- 选中带 move / attack / AMOV / HOLD / Carrier guard 的玩家单位后点击 STOP，目标字段全部清空，选择保持，命令意图线立即消失。
- STOP 不改变单位 HP、攻击计时器、经济、AI、迷雾、任务或胜负。
- STOP 副标题能区分 `n cmd` 与 `idle`；无单位和全 idle 不 crash，并给出可理解提示。
- STOP marker 清楚显示 `STOP n`，不遮挡模型、HUD、小地图或选择面板。
- `simulator-stop-command.png` 能同时证明 STOP 按钮、跨域多选、无命令意图线和世界确认反馈。
- 最新 `origin/main` artifact 的 generic iOS build、simulator build、二十次 launch / alive / PNG 均成功；JUnit 0 failures，无 crash / SIGABRT / watchdog / fatal。

## 风险

- tactical 页多一个动作会压缩按钮宽度，必须依赖现有 responsive 计算并在云端截图检查最长副标题无溢出。
- Carrier HOLD 清理后若先调用有效 anchor helper再取 wing，会丢失释放对象；必须先快照、后清理。
- capture mode 冻结 update loop，若只等待自然刷新，旧 guard anchor 或命令线可能残留；STOP helper 必须同步清理并主动刷新。
