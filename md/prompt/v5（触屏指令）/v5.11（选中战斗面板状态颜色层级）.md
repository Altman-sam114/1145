# v5.11 / 选中战斗面板状态颜色层级

## 版本号与版本分配依据

- 版本号：v5.11。
- 分配依据：v5.10 已在 main 完成六格竖直分段耐久塔；本轮仍属于 v5 触屏识别阶段，继续做一个不改变规则的战斗 UI 增量，因此按小版本递增为 v5.11。
- 本轮只改选中信息面板的视觉层级，不新增战斗系统、世界标记或地图地物。

## 背景与参考

- 参考对象固定为百度百科 lemma 4042982 对应的 Noble Master Games《沙漠风暴 Desert Stormfront》，不是其他同名作品：
  https://baike.baidu.com/item/%E6%B2%99%E6%BC%A0%E9%A3%8E%E6%9A%B4Desert%20Stormfront/4042982
- 官方 Press Sheet：https://www.noblemaster.com/press/sheet.php?p=desert_stormfront；官方视频：https://www.youtube.com/watch?v=7oZC6DpIUhQ。参考其触屏 RTS 的信息优先级：玩家需要在不离开战场的情况下快速区分“自己是否濒危、主目标还剩多少、武器是否可用、是否正在被集火”。本轮只借鉴层级与对比度，不复制原素材、纹理、音频或布局。
- 当前原型已有 v4.91 的单选 / 多选战斗摘要、主目标 HP 与底部目标生命条，v4.92 的来袭威胁摘要，v5.9 的 ATK / FOCUS 世界标记，v5.10 的旗标与六格实体耐久塔。选择面板中的文本行目前基本都是同一浅色，玩家仍需逐行阅读才能判断优先级。
- 本轮不再叠加新的世界文字或环形标记，避免与 ATK、FOCUS、IN、旗标和耐久塔互相遮挡；只利用现有面板行、既有文字和既有目标生命条完成状态分层。

## 本轮目标

1. 为选择信息面板建立稳定、可复用的状态色板，并在每次 updateSelectionInfoPanel(selected:) 刷新时为当前行设置颜色；所有行在下一帧都必须被重新赋值，不能保留上一种选择的颜色。
2. 单选玩家作战单位或建筑：
   - 自身 HP 行沿用现有伤害语义：满血 / 正常为清晰绿色或青绿色，DMG（HP ratio <= 0.62）为琥珀色，CRIT（HP ratio <= 0.35）为高对比红橙色。damageStateShortLabel(for:) 仍是状态来源，不重新计算第二套 HP。
   - 有合法、存活且玩家已知 primaryCombatTarget 时，Tgt ... HP ... 行按既有目标生命条阈值着色：ratio > 0.55 绿色、> 0.25 琥珀色、<= 0.25 红橙色；底部 selectionTargetHealthFill 的几何、阈值和左对齐缩放保持一致。
   - Weapon ready 使用青绿色 / 绿色；Reload x.xs 使用琥珀色；没有目标时不伪造武器就绪状态，保持中性文字。weaponReadinessLine(for:) 仍只读 attackTimer。
   - 单选单位只有来袭威胁而没有主目标时，现有 INCOMING ... 行使用红橙色；同时有目标和来袭威胁时，不删除任何既有文本，目标行继续表达输出侧，武器行中的 INn ... 以红橙色或清晰的红橙强调表达输入侧风险，不能让 IN 看起来像普通 reload 文案。
3. 多选玩家部队：
   - HP ... Wnd ... Crit ... 行根据当前选中集合设置优先级：存在 Crit > 0 时红橙色，只有 Wnd > 0 时琥珀色，全员完整时绿色 / 青绿色；不得改变计数和总 HP 文本。
   - PRIMARY ... 行按主目标 HP ratio 使用与目标生命条相同的绿 / 琥珀 / 红橙色；没有主目标时，该行位置或 Dmg / Max rng 行保持中性，不得把普通编队统计误染成目标状态。
   - 最后一行的 Eng ... Rdy ... 在无来袭威胁时按武器就绪情况表达：全部可开火为绿色，有部分装填为琥珀色；有合法来袭威胁时红橙色优先，保留 In attacker/target 文本。标题已有的 IN n 红橙色行为必须保留。
4. 颜色只能强化现有文字语义，不能成为唯一信息来源：保留 HP、DMG、CRIT、PRIMARY、Weapon ready、Reload、INCOMING、IN 等已有短码和数值。不要为了颜色新增行、缩小字号或重排面板。
5. 所有非战斗上下文恢复既有中性浅色：空选择、建筑施工 / 生产、集结点、攻击移动目标、支援目标、航母队列和海岸资产说明不得继承上一次战斗选择的红 / 琥珀 / 绿色。
6. 状态色板必须在黑色半透明面板和 iOS 小屏缩放下保持高对比，使用现有青绿、绿色、琥珀、红橙体系，不引入紫色渐变、外部素材或新的字体。

## 非目标

- 不新增世界 SKShapeNode、攻击线、方向箭头、伤害飘字、爆炸、炮线、模型、地图地物、HUD 按钮、页签、弹窗或外部依赖；不得重复 v5.9 / v5.10 已完成的标记和耐久塔。
- 不改变选择面板尺寸、行数、行距、目标生命条位置 / 宽度 / 左对齐缩放、命令条触控区域、顶部任务面板或小地图布局。

- 不修改 .github/workflows/ci-results.yml、不增加新的 launch / PNG，不运行本地 Xcode build、本地 simulator、本地截图或本地玩法探针。

## 当前架构依据

- GameScene.swift 是当前事实核心；updateHUD() 先取得存活选中实体，再刷新 refreshIncomingThreatVisuals、refreshFocusFireMarker 和 updateSelectionInfoPanel(selected:)。
- addSelectionInfoPanel(frame:compact:) 一次性创建 selectionInfoTitleLabel、selectionInfoRowLabels 和 selectionTargetHealthBack / selectionTargetHealthFill。本轮应复用这些节点；不得在 updateHUD() 或 updateSelectionInfoPanel 中逐帧 addChild 新节点。
- selectionInfoContent(for:)、singleSelectionInfo(for:)、groupSelectionInfo(for:) 继续生成现有文案；不应通过解析字符串猜状态。可新增只读的 selectionInfoRowColors(for:) / 状态枚举，或让 content 返回与 rows 对齐的颜色元数据，但要保持现有调用者简洁。
- damageStateShortLabel(for:) 使用 0.62 / 0.35 伤损阈值；updateSelectionTargetHealthBar(selected:) 当前使用 0.55 / 0.25 的目标条颜色阈值。两套阈值均是既有语义，本轮不得擅自合并或改变。
- primaryCombatTarget(for:) 只统计玩家选中、存活、作战、已知且仍有合法 attackTarget 的单位；incomingThreatSummary(for:) 只统计满足迷雾和合法攻击边界的敌方攻击者。本轮颜色应直接使用这些 helper 的结果，不另建战斗快照或写回 attackTarget。
- selectionInfoTitleLabel 当前在有来袭威胁时变为红橙色；selectionTargetHealthFill 当前按目标 ratio 左对齐填充。两者的既有行为必须保留，并与行色板共存。
- 行标签当前是统一 Menlo 小字号；应只改变 fontColor / 必要的透明度，不改变 fontSize、对齐方式、位置、文字长度或字体。

## 实现步骤

1. 开始前执行 git fetch origin、git switch main、git pull --ff-only origin main，确认本地 main == origin/main。保留人工未暂存的 Team ID 和 Unity 分析目录，不得用 reset / checkout 覆盖。
2. 阅读 addSelectionInfoPanel、updateSelectionInfoPanel、selectionInfoContent、singleSelectionInfo、groupSelectionInfo、updateSelectionTargetHealthBar、damageStateShortLabel、weaponReadinessLine、primaryCombatTarget 与 incomingThreatSummary，先确认颜色只在 HUD 读路径。
3. 在 GameScene 内定义紧凑的 HUD 状态色板和只读行状态映射。优先使用枚举 / 直接状态数据，不要从已生成的字符串中搜索 HP、IN 或 Reload；默认色必须集中定义，避免每个分支散落不同 RGB。
4. 在 updateSelectionInfoPanel(selected:) 中先设置标题和行文本，再为所有现存行逐一重置 fontColor。按上下文给单选 / 多选的 HP、目标、武器、来袭行赋色；若某行未使用或当前模式不是战斗面板，恢复既有 UIColor(white: 0.90, alpha: 1.0)。
5. 复用目标生命条的 ratio / 颜色 helper，保证 PRIMARY 文案颜色、目标生命条颜色和世界 FOCUS 的生命语义不互相矛盾；不要改 selectionTargetHealthFill 的 xScale、位置或阈值。
6. 检查状态优先级：CRIT 高于 DMG；来袭 IN 高于多选武器就绪色；有合法主目标时目标行优先表达目标 HP；没有目标时不得显示 Weapon ready 作为伪目标确认。所有已有文本仍必须可读。
7. 只在 capture mode 之外不改变任何状态写入；不要为颜色新增 capture 场景、临时目标、HP、reload 或 attackTarget。现有 24 张 probe 继续复用即可。
8. 同步真实行为文档（Agent B 实现后完成）：README.md 记录选中战斗面板的颜色层级和既有文本语义；md/flow/flow.md 记录 HUD 只读状态到行色板的映射、阈值和迷雾边界；md/flow/flowchart.md 在选择 / 战斗态势节点补充“文本 + 状态色 + 目标条”路径；md/test/test.md 保留 24 次 launch 数量并补充截图目视检查项。Agent B 不预写 update_log.md 的云端通过结论。

## 风险和禁止项

- 颜色过暗会在沙地 / 海面截图中失去层级，颜色过亮会抢过战场主体；必须使用高对比但低饱和的现有 HUD 色板，并保留文字作为第二信号。
- 单选目标和多选总 HP 的阈值不同，不能为了“统一”而修改 v5.10、v4.91 或伤损系统的既有阈值；应在 helper 中明确区分自身状态与目标状态。
- 选中对象从战斗单位切换到建筑、支援目标或空选择时最容易残留上一帧颜色；所有行每次刷新都要显式恢复默认色。
- incoming 优先级不能覆盖合法主目标的 HP 语义，也不能把普通 Rdy 文字染成红色而隐藏真正原因；需要保持现有 IN 文案和标题红橙提示。
- 禁止把颜色更新放入 updateCombat、fire 或 HP 写入；禁止新增每帧节点、随机动画、外部素材、依赖、workflow launch 或本地完整测试。
- 禁止将人工 Team ID、md/unity分析/、构建产物、旧 artifact 或无关格式化纳入提交；禁止使用非 Altman-sam114 账号完成 push 或 artifact 验收。
