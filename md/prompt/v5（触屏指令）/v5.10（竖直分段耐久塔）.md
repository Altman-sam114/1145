# v5.10 / 竖直分段耐久塔与阵营旗标对齐

## 版本号与版本分配依据

- 版本号：`v5.10`。
- 分配依据：`v5.9` 已在 `main` 完成红色虚线攻击目标环与橙色双 V（实现提交 `6b4e331`，云端验收日志提交 `2dfef68`）。本轮不改变命令或目标规则，继续在 v5 触屏识别阶段做一个单一共享实体视觉增量。
- 官方截图中每个单位旁的“竖直分段耐久塔 + 阵营旗杆旗标”是跨陆、海、空都稳定可读的识别语言，适合在现有 24 张云端截图中验收，因此顺序递增为 `v5.10`。

当前原型已有 v5.5 旗杆旗标，但仍使用细的水平生命条；本轮只收紧这两层的空间关系，让玩家在小屏幕、缩远镜头和海空混战中更快判断单位状态。

## 本轮目标

1. 为已有生命条的 `GameEntity` 建立一个固定尺寸、竖直排列的 5-6 格耐久塔。每格有深色空槽和清晰边缘，已损失格保持可见，填充格数量由现有 HP ratio 决定；不得用文字替代分段视觉。
2. 将耐久塔放在现有 `teamFlag` / `flagPole` 的固定邻侧，保持 flag 作为阵营识别主标识，避免耐久塔覆盖旗布、实体短码、选择圈、FOCUS、ATK 或血条文字。位置和总高度须按 `kind.footprint` 做有限 clamp，小 Fighter、AA Truck、Battleship、Carrier 和结构都不能无限放大。
3. 将当前水平 `healthBack` / `healthFill` 的可见视觉替换为竖直塔，避免同时出现两套完整生命条造成拥挤。若为保留兼容性继续持有 `healthFill` 字段，可以隐藏或作为内部兼容节点，但屏幕上只能有一套主耐久提示。
4. 保留既有颜色与状态语义：`entity.hp / entity.kind.maxHP` 仍是唯一 ratio 来源，`updateHealthBar(_:)` 仍是唯一刷新入口；绿色/受损红色阈值和 `updateDamageStateVisual(...)` 的战损效果不能因本轮改变。
5. 塔和旗标继续挂在 `entity.node` 下，沿用实体现有 z 层级和战争迷雾父节点隐藏链路。未知敌军、未侦测潜艇和未探索格绝不能因耐久塔新增显示而泄露。
6. 不新增 workflow launch 或素材；使用当前 24 张 simulator PNG 做跨域 UI / 战斗验收。

## 当前架构依据

- `GameEntity` 的共享节点字段位于 `DesertFrontline/GameScene.swift:857-890`：当前有 `healthFill`、`teamFlag`、`label`，所有陆海空单位和建筑共用同一实体父节点。
- `GameEntity.init(...)` 在 `:892-910` 创建水平 `healthFill`（约 5pt 高）和旗布 path；本轮如新增 `[SKShapeNode]` 分段节点，必须一次性在初始化/配置阶段建立，不得在 `update` 循环中反复创建。
- `configureEntityNode(_:)` 的生命条与旗标配置在 `:2094-2128`：`healthBack` / `healthFill` 为 z20/21，`teamFlag` 为 z22，旗杆和杆顶是旗标子节点。新的耐久塔应位于相近本地层级、低于旗标、且仍随 `entity.node` 经过 fog。
- `setFaction(_:,for:)` 在约 `:7828-7833` 只更新 `teamFlag.fillColor` 和标签；本轮不得复制平行阵营状态，耐久塔不应成为新的 faction 数据源。
- `updateHealthBar(_:)` 在 `:9551-9558` 计算 `ratio = clamp(entity.hp / entity.kind.maxHP)`、设置当前填充颜色并调用 `updateDamageStateVisual(...)`。保留该 ratio 和调用链，只把视觉写入改为已存在的分段节点集合；不得在塔内重新推导 HP 或修改数值。
- `updateFog(force:) / isKnownToFaction(...)` 仍控制 `entity.node` 的可见性；耐久塔必须是实体子节点，不能放进全局 `effectsLayer`。
- v5.9 的 `showAttackTargetMarker(...)`（`:11643-11704`）已经提供红色虚线 footprint-aware 目标环、橙色双 V 和下置 `ATK` 标签；新塔要与它、FOCUS 双环 / 八段目标血条及旗标共存，不得触碰这些 helper。

## 验收标准

- 共享 `GameEntity` 的所有生命可见实体都有一套稳定、竖直、分段的耐久塔；塔不会因 footprint 无限增长，且与 `teamFlag` / `flagPole` 形成清晰的“旗标识阵营、耐久塔识状态”组合。
- `updateHealthBar(_:)` 仍以 `entity.hp / entity.kind.maxHP` 的 clamp ratio 驱动，直接火力、支援、维修、capture reset、damage-state 与 skirmish 重开均更新正确；没有第二套 HP 数据流。
- 塔仍在 `entity.node` 下，遵守现有 fog / known-to-faction 隐藏；未知敌军和未侦测 Submarine 不会通过塔泄露位置。
- 旧水平主生命条不与新塔重复显示；实体短码、旗标、选择圈、damage smoke/fire、FOCUS/ATK marker、海空反馈和 HUD 均无遮挡。
- 24 张 PNG、generic device build、simulator build、PID 检查、JUnit、日志和 manifest 全部通过；最新 `origin/main` 对应 run conclusion 为 `success`。

## 风险和禁止项

- 小 footprint 的 Fighter / AA Truck 在 `enemy-touch-assist` 缩放下最容易发生旗标、塔和短码碰撞；必须用本地 clamp 与 `xScale` 镜像验证，不能靠把塔移进 `effectsLayer` 解决。
- 空中单位、Carrier / Battleship、结构的 footprint 和 zPosition 不同；不得用单一超大尺寸，不能覆盖航迹、舰炮、烟火、水柱、ASW、FOCUS 或 ATK 标签。
- 分段塔只能是视觉读数；禁止用塔格数写回 HP、伤害、攻击优先级、冷却、AI 或任务状态，禁止每帧创建/销毁 `SKShapeNode`。
- 禁止改变 `health` 写入调用、`setFaction` 旗标换色、fog / sonar / `isKnownToFaction`、攻击 marker 或 workflow；禁止新增外部素材/依赖、随机动画、截图或本地完整测试。
- 禁止把人工 Team ID 修改、`md/unity分析/`、构建产物和无关格式化纳入 staged/commit；禁止使用非 `Altman-sam114` 账号完成 push 或 artifact 验收。
