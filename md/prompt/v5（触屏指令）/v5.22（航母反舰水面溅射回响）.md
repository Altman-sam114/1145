## 2. 背景与当前架构依据

- DesertFrontline/GameScene.swift 是当前事实核心。GameScene.update(_:) 驱动战斗，fire(attacker:target:) 统一执行伤害、HP、击杀、AI 防御、迷雾与胜负链路，并在既有可见性条件下派发视觉效果。
- fire(attacker:target:) 对 attacker.kind == .carrier 且攻击者对玩家可知时，水面海军目标进入 launchCarrierWing(...)；该函数只负责舰载机三机进场、反舰弹轨迹和最终视觉命中，不应把视觉延迟变成真实攻击延迟。target.hp 仍在 fire(...) 的原位置一次写入，航母特效不参与碰撞或命中判定。
- 当前 launchCarrierWing(...) 已有两个入口语义：普通运行在约 0.72s 后调用一次 showCarrierStrikeImpact(...)；persistent == true 的 capture 直接创建完整的静态舰载机 / 反舰弹 / 命中构图。普通和 persistent 都必须只产生一次命中反馈。
- 当前 showCarrierStrikeImpact(...) 对 surfaceTarget 只调用 showNavalHullStrike(...)，对非水面目标仍调用 showAirMissileImpact(...)。本轮应把水面溅射的唯一归属加到这个既有 surface impact helper 链路中，保留舰体命中 helper；不得在 fire(...) 另建分支，也不得调用完整 showNavalSalvoImpact(...) 造成战列舰式重复水柱。
- showNavalWaterImpact(...) 已提供浅青 / 白色水柱、椭圆洗浪、内环、浪冠和水滴的复用视觉。它将节点挂到 effectsLayer：persistent == true 立即保留完整静态节点，普通模式约 0.56s 后通过 removeFromParent() 清理，并由子节点动作完成淡出。新增调用必须沿用这个生命周期和可见性 guard。
- .github/workflows/ci-results.yml 的 carrier-strike fixture 是第十五次既有启动：prepareCICarrierStrikeCaptureScene() 先布置 Carrier / Red Battleship，再调用 launchCarrierWing(..., persistent: true)，随后目前还单独调用了一次 showNavalWaterImpact(...)。这次独立调用会与新的统一 impact helper 重复；实现时必须移除该 fixture 直调用，让 launchCarrierWing 的 persistent 路径成为唯一来源。不得新增第 25 次 launch、marker、PNG 或 workflow 分支。
- 现有 effectsLayer、舰体模型、航迹、Carrier 甲板 / 护航圈、FOCUS / ATK、目标 HP / 距离 / reload、战争迷雾和潜艇 / ASW 规则均是已验收事实。本轮只叠加 SpriteKit 节点，不新增运行态字段、事件总线或平行海战系统。

## 3. 单一目标与具体范围

1. 在 showCarrierStrikeImpact(...) 的 surfaceTarget 分支中，保留一次 showNavalHullStrike(...)，并复用 showNavalWaterImpact(...) 生成一组紧凑水面反馈。建议由一个较明显的近舷主溅射和一个更小、略错位的近失回响组成；总尺寸必须小于或接近现有 Battleship / Coastal Battery 双水柱，不能覆盖整艘目标舰体。
2. 水面反馈的点位必须相对 point 和 Carrier 到目标的来袭方向确定。可以从 launchCarrierWing(...) 已有的 direction 传递一个可选的 normalized incomingDirection 给 showCarrierStrikeImpact(...)，再把同一方向传给 showNavalWaterImpact(...) 以复用其椭圆旋转；这只是函数参数和局部几何，不得写入实体、目标或战斗状态。若使用 fallback，必须是稳定的局部几何，不得依赖随机数或截图时机。
3. 水柱和近失回响必须使用当前玩家 / 敌方颜色语言：沿用 showNavalWaterImpact(...) 的浅青、白色和现有阵营 accent；不得引入新素材、粒子框架、外部依赖或新的颜色体系。
4. persistent == true 的 carrier-strike capture 必须一次创建完整的舰载机、两枚反舰弹、主溅射、近失回响、舰体命中、伤害飘字和 HUD 构图；不得靠等待 0.72s、动画进度或截图恰好落在某个时间点才能看到水面反馈。
5. 普通运行只允许在现有 showCarrierStrikeImpact(...) 触发时创建一次这组特效。水面子节点沿用 showNavalWaterImpact(...) 的短 fade / scale / removeFromParent() 路径，不能延迟 fire(...)、HP 写入、attackTimer、冷却或 AI。

## 10. 风险与处理

- showNavalWaterImpact(...) 的水柱高度、椭圆洗浪和水滴会随 scale 放大；主点 / 回响点若离目标过近会遮住舰体，过远又会像无关爆炸。使用局部、确定性的相对偏移和小尺度，并在 carrier-strike 截图中同时检查舰体、目标血条和 HUD。
- showCarrierStrikeImpact(...) 既服务普通动画又服务 capture。任何只写在普通分支的水柱都会在 persistent 截图消失；任何把 wait / fade 加到 persistent 分支的实现都会导致截图依赖时机。两种模式必须共用创建逻辑，但只让普通模式进入 helper 原有动作。
- 现有 fixture 已有一次手动 showNavalWaterImpact(...)。若不删除它，统一 helper 会产生重复水柱；若同时删除 launchCarrierWing 的 impact，又会破坏普通运行和统一入口。最终只能保留 launch -> impact helper 这一条来源。
- Carrier 的 fire(...) 不经过 shouldShowNavalWaterImpact(...) 的 Battleship / Coastal Battery 分支；不要为了复用而放宽该 guard 或让 Carrier 走 showNavalSalvoImpact(...)，否则会改变其他海军反馈和 fog 语义。
- effectsLayer 的 z 序高于实体但低于 HUD / fog 的实际关系必须保持。局部 z 调整只有在证明必要时才能做，并须保持舰载机、反舰弹、舰体闪光、溅射、FOCUS / ATK 和耐久塔的可读层级。
- 多次普通齐射会频繁创建短节点；必须沿用 removeFromParent()，不得添加常驻 timer、无限 action、通知监听器或每帧绘制，避免重开 / 场景切换后的残留和性能回归。
