## 背景

当前原型已有：

- GameEntity 的 Carrier 几何模型：舰体、双层甲板、斜角跑道、虚线中线、起飞阈值、停机位圆点、舰岛、舷窗和桅杆；
- carrierDeckCapabilityLine()、carrierDeckQueueAndRallyLine(for:)、carrierAirWingLine(for:) 组成的选中航母信息面板；
- launchCarrierWing(...)、showCarrierLaunch(...) 和现有 CI carrier-strike capture 提供舰载机进场、反舰弹和水面命中反馈；
- GameEntity.productionNode 对生产队列做实体内提示，carrierGuardAnchorCoverageNode 对 HOLD 航母警戒半径做独立覆盖圈。

现有 carrier-strike 云端截图能看到航母整体与三机进场线，但 Carrier 本体的甲板停机位仍只是两个小圆点，选中面板的 Deck HEL/JET 也没有直接告诉玩家“甲板可容纳三架可视化待命机位”。需要一次低遮挡、纯视觉的甲板细化，让航母在海战 / 空战混合画面中更像可操作的海上空军基地，同时不与已有实体状态混淆。

## 本轮目标

1. 在 GameEntity 中为 Carrier 增加一个独立、预创建的 carrierDeckAircraftNode（或同等清晰命名），挂入 Carrier 实体 node 子树；非 Carrier 实体保持隐藏且不创建 world-level 节点。
2. 在 configureEntityNode(_:) / Carrier 模型配置阶段一次性创建三组停机位视觉：
   - 三个沿现有斜角跑道方向错列的低透明停机位轮廓；
   - 每个位由一个短机身 / 小翼面几何和一个深色甲板底座组成，优先复用 carrierLaunchCraft(for:faction:) 的几何语言或等价轻量 SpriteKit path，不新增贴图；
   - 轮廓必须比真实舰载机小、放在甲板局部范围内、避免盖住舰岛 / 甲板中线 / 阈值 / 旗标 / 六格耐久塔 / 选中圈；
   - Blue 使用青绿色低亮边线，Red 使用橙红低亮边线，Neutral 不适用；隐藏状态使用与实体相同的 fog / death / restart 父节点边界。
3. 停机位只读当前 Carrier 的运行状态：
   - 未选中时保持低 alpha 常驻，以便玩家辨识“甲板”；
   - Carrier 处于 player HOLD 且存在绑定 guard wing 时，最多将三个停机位中对应的 Hn/Jn 数量切换为更亮的 ready / bound 色；没有绑定翼队时不伪造飞机数量；
   - 生产队列正在制造 HEL/JET 时，至少一个停机位可以显示一条短琥珀装填条或轮廓强调，但不得新增生产字段；直接读取现有 buildOrders、boundCarrierGuardWing(for:) 和 carrierAirWingCompositionSuffix 相关状态；
   - 其余停机位保持深色空槽。不得改变 buildOrders、guardAnchorCarrierID、holdPosition、攻击、起飞、AI 或资源。
4. 新增一个只读显示 helper（如 refreshCarrierDeckAircraftVisuals()），每帧只切换已预创建节点的 isHidden、alpha、strokeColor、fillColor 或子节点属性；禁止在 update loop / updateHUD 中 addChild、removeFromParent、removeAllChildren 或重建 path。
5. 只读扩充选中 Carrier 面板的现有文案：把 carrierDeckCapabilityLine() 从 Deck HEL/JET 改为紧凑、真实的 Deck 3-pad HEL/JET（或同等短文案），并在 carrierDeckQueueAndRallyLine(for:) 中保留现有 Rally / Queue / GW / Hn/Jn 信息；不得增加新 HUD 行、按钮、输入或页签。
6. 保持现有海空视觉边界：
   - carrier-strike 中三条进场线、三架进场机、两枚反舰弹、水面命中和 damage floater 继续可见；
   - carrierGuardAnchorCoverageNode、escortCoverageNode、navalGunRangeNode、landAirCombatRangeNode 不复用、不改色、不改变显示资格；
   - 敌方 Carrier 只有在既有 isKnownToFaction(...) / fog 规则允许时才可见，停机位不得泄露未知敌方位置；
   - Carrier 的既有 productionNode、旗标、六格耐久塔、selection/readiness、wake、模型、HUD 和 minimap 不回归。

## 非目标

- 不改变 EntityKind、buildOrders、guardAnchorCarrierID、holdPosition、攻击合法性、伤害、冷却、AI、经济、生产、HOLD / guard wing 绑定、任务、胜负、迷雾、声呐或重开逻辑。
- 不新增外部图片、音频、字体、依赖或第三方库；不修改 .github/workflows/ci-results.yml，不增加第 25 次 launch 或 PNG。
- 不把新停机位挂到 effectsLayer、HUD、小地图或其他独立 world 层；不为停机位建立第二套选中集合或状态存储。

## 当前架构依据

- GameScene.swift 是事实核心；GameEntity 已持有 node、productionNode、selectionNode、navalWakeNode、airShadowNode 和各类实体内覆盖节点。
- configureEntityNode(_:) 是实体视觉的一次性构造入口；Carrier 几何在 addNavalUnitBody(for:to:) 的 .carrier 分支中构造，已有 runway / dash / threshold / pad / island 节点。
- updateHUD() 每帧刷新 refreshSelection() 与只读状态；updateBuildOrders(dt:) 与 updateProductionIndicators() 是现有生产状态来源；boundCarrierGuardWing(for:) 是既有 HOLD guard wing 来源。
- entity.node.isHidden 是敌方 fog / 潜艇可见性父节点边界；实体树节点随移动、xScale 镜像、死亡清理和 restartSkirmish() 生命周期。
- 现有 carrierAirWingLine(for:)、carrierDeckCapabilityLine() 和 carrierDeckQueueAndRallyLine(for:) 已提供玩家可见语义，本轮只增强其精度，不另建 HUD 系统。

4. 设计紧凑几何：沿现有 runway 的斜角方向排布三个小型 carrierLaunchCraft 风格轮廓，尺寸约为真实 Carrier 的 0.18–0.26；底座、短机身、翼面和微弱机头朝向要在 1206×2622 纵向云端截图中可辨，但不能让甲板看成三架正在飞行的独立实体。

6. 添加只读刷新 helper。每帧先把所有 Carrier 停机位恢复为空槽 alpha / color，再计算：
   - boundCarrierGuardWing(for: carrier) 中的 HEL/JET 数量；
   - buildOrders 中该 Carrier 当前 active / queued 的 HEL/JET 数量；
   - Carrier faction / isAlive / isOperational / node.isHidden。
   将最多三个固定停机位按稳定顺序显示为 bound（青绿 / 橙红高亮）、queue（琥珀短条）或 empty（暗色）。这些视觉只是现有状态摘要，不得写回任何实体状态。

8. 将 carrierDeckCapabilityLine() 改为 Deck 3-pad HEL/JET（或等价不溢出短文案），保留其他现有 carrier 面板行、颜色层级和 carrierAirWingLine 内容；不得新增文字行。

## 风险与禁止项

- 风险：纵向小屏下 Carrier 本体、停机位和旗标 / 耐久塔靠得很近。使用固定小几何、低 alpha、稳定 zPosition；不要扩大 Carrier footprint、selection ring 或 HUD。
- 风险：把附近空军误画成甲板飞机。只使用绑定到该 Carrier 的 guard wing 和该 Carrier 自己的现有空军生产队列摘要；空槽保持空，不根据距离猜测待命机。
- 风险：敌方 fog 位置泄露。新节点必须在 entity.node 下，不允许 effectsLayer / minimap 独立显示。
- 禁止改变 EntityKind、buildOrders、guard anchor、attackTarget、attackTimer、AI、经济、生产、迷雾、声呐、任务、胜负或 restart 数据流；禁止新增外部依赖、素材、workflow launch、截图或测试专用状态。
- 禁止使用 reset / checkout 覆盖用户改动，禁止暂存或提交 Team ID、md/unity分析/、构建产物、未提交日志或其他无关变化。
