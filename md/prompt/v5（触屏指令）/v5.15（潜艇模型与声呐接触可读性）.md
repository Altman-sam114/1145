# v5.15 / 潜艇模型与声呐接触可读性

## 版本号与版本分配依据

- 版本号：`v5.15`。
- 分配依据：当前 `main` 的 v5.14 日志提交为 `9916e33d08f91ca25cb0b25e0ebc84b9b927fbc6`，航母甲板三停机位已有云端验收；源码审查确认潜艇仍主要由“椭圆舰体 + 简单指挥塔”表达。继续 v5 触屏指令阶段，做一个可由既有海战探针验证的有限海军模型增量。
- 参考资料：Noble Master Games 官方 [Desert Stormfront press sheet](https://www.noblemaster.com/press/sheet.php?p=desert_stormfront)、[官方预告片](https://www.youtube.com/watch?v=7oZC6DpIUhQ)、[itch.io 页面](https://noblemaster.itch.io/desert-stormfront) 和 [IndieDB 截图页](https://www.indiedb.com/games/desert-stormfront/images/screenshots-for-desert-stormfront)。这些资料只作为海岸、海战和触屏信息层级参考，不复制图片、纹理、模型或外部素材。

## 背景

- `GameScene.swift` 的潜艇当前由 `addNavalUnitBody(for:to:)` 的 `.submarine` 分支绘制一枚椭圆舰体和矩形指挥塔；已有低透明航迹、`revealedUntil` 暂时暴露、迷雾已知判定、声呐检测和 `submarineStatusLine(for:)`。
- 现有 `simulator-naval-damage` 已同时展示 Red Submarine、反潜命中、声呐/命中效果和血条，是本轮最直接的视觉证据。不能把已有文本状态误认为已覆盖所有真实隐身转换；本轮只增强实体树内模型和只读可视提示。
- 所有潜艇位置仍必须由 `node.isHidden`、`isKnownToFaction(...)` 和现有迷雾链路控制。新节点不能挂到全局效果层，也不能在未知敌军或未侦测潜艇上泄露位置。

## 本轮目标

1. 将潜艇模型从简单椭圆扩展为方向明确但克制的 SpriteKit 几何模型：舰体高光/龙骨层、指挥塔、潜望镜、尾舵/螺旋桨、艇艏声呐穹顶和两个鱼雷口/舱盖等细节。所有几何均使用现有代码路径和 faction 配色，不引入图片或外部依赖。
2. 保留现有潜艇低透明航迹，并让新细节保持“隐蔽目标”的低对比度语义；不可用过亮轮廓把潜艇变成普通水面舰船。
3. 增加一个实体本地、只读的潜艇接触 cue：
   - 仅对玩家当前选中的潜艇，或已经满足现有 `isKnownToFaction(entity, observer: .player)` 的敌方潜艇显示；未知敌军和未侦测潜艇必须隐藏。
   - 选中的玩家潜艇根据现有状态显示短标签/颜色：`STEALTH`、`SONAR` 或 `DETECT`；已知敌方潜艇只显示中性可读的 `CONTACT`，不得猜测其未暴露原因。
   - cue 只读 `revealedUntil`、`isCoveredByKnownEnemySonar(...)`、选中集合和现有已知判定，不新增探测字段、计时器、攻击规则或网络状态。
   - cue 使用小型环/短标签，不能遮挡舰体、血条、`ASW HIT`、声呐波纹、FOCUS 或 HUD；不做持续闪烁、不逐帧创建节点。
4. 保持当前潜艇状态文本 `submarineStatusLine(for:)`、声呐范围、反潜合法性、攻击伤害、AI、生产、经济、迷雾和重开流程不变；本轮只让既有状态更容易读懂。
5. 不新增第 25 张截图，不改既有 24 次 capture；复用现有云端 PNG 验收模型和回归层级。

## 非目标

- 不修改 `revealedUntil` 的赋值或持续时间、`isKnownToFaction(...)`、`visibleTiles`、`exploredTiles`、`supportRevealTiles`、声呐范围、`canAttack(...)`、ASW 伤害、攻击冷却、AI 反潜行为、经济、生产、任务、胜负或重开 skirmish。
- 不新增潜艇实体、鱼雷武器、声呐技能、探测状态枚举、命令按钮、HUD 页面、触控命中区域、捕获场景状态或测试截图。
- 不修改 Battleship、Carrier、空军、陆军和普通水面舰船的模型逻辑；不让 Carrier 甲板节点出现在潜艇上。
- 不绕过实体树挂接效果，不把未知敌方潜艇放入全局 `effectsLayer`，不以新 cue 推断攻击方向、AI 目标、弹道或潜艇具体位置。
- 不新增外部依赖、素材、纹理、音频、随机粒子或大范围重构；不修改 `.github/workflows/ci-results.yml`。
- 不运行本地 Xcode build、本地 simulator、本地截图或本地玩法探针。

## 当前架构依据

- `GameEntity` 是单位运行态对象；已有 `navalWakeNode`、选择圈、血条和多种局部视觉节点。新增潜艇 detail/cue 节点应作为 `GameEntity` 的局部子节点，并在 `configureEntityNode(_:)` 统一配置。
- `addNavalUnitBody(for:to:)` 负责 Battleship/Submarine/Carrier 的几何模型；本轮主要改 `.submarine` 分支，不复制一套平行海军单位系统。
- `configureNavalWakeNode(for:)` 和 `updateNavalWake(for:direction:)` 已处理潜艇低透明航迹；保持其透明度、生命周期和方向更新语义。
- `updateHUD()` 已统一刷新选择、武器、射程、航母甲板、来袭威胁和指令视觉；新增 cue 可在这里调用一个无状态的 `refreshSubmarineContactCueVisuals()`，仅更新预创建节点的 `isHidden`、颜色和文字。
- `submarineStatusLine(for:)` 已提供 `Temporary detected`、`Known sonar contact` 和 `Stealth / no known contact` 等事实文本；新 cue 必须是其简化视觉提示，不能取代或改写该状态判断。
- `isCoveredByKnownEnemySonar(_:)` 只对玩家潜艇成立；敌方潜艇 cue 不得调用它来伪造敌方探测来源，只能使用 `CONTACT`。

3. 在 `configureEntityNode(_:)` 中按实体树顺序挂接潜艇细节和 cue；保证新节点随实体一起受父节点隐藏、销毁、重开和迷雾逻辑影响。非潜艇实体的新增节点必须保持隐藏且不改变原有模型。

5. 新增一个局部 cue 刷新函数：
   - 先隐藏所有非潜艇、死亡、不可见或不满足已知/选中条件的 cue；
   - 对玩家选中潜艇按 `revealedUntil > lastUpdateTime`、`isCoveredByKnownEnemySonar(...)`、其他状态选择 `DETECT` / `SONAR` / `STEALTH`；
   - 对已知敌方潜艇显示 `CONTACT`；
   - 只更新已有节点的位置、颜色、alpha、文本和可见性，不更改实体状态。
6. 不修改 `fire(...)`、`showAntiSubmarineHit(...)`、`showSonarPing(...)`、`revealSubmarineHitBySupport(...)`、`updateFog(...)`、`isKnownToFaction(...)` 或反潜目标合法性。新模型应自然出现在已有 `simulator-naval-damage` 的命中效果下面/旁边，不新增命中特效。
7. 同步 `README.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md`：只写当前已经实现的潜艇几何细节、实体本地 cue、既有迷雾/声呐边界和 24 张探针复用；不得宣称新增真实隐身转换、触控体验或长时间战斗验证。
8. 完成后仅运行允许的本地轻量检查，按 `v5.15: 潜艇模型与声呐接触可读性` 提交并直接推送 `origin/main`；等待该实现 SHA 对应的 GitHub Actions 云端结果后交给 Agent C 核对。
