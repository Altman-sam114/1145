# v5.8 / 战列舰战损与反潜命中细节

## 版本号与版本分配依据

- 版本号：`v5.8`。
- 分配依据：`v5.7` 已完成海岸浅水与开阔水面细化，`update_log.md` 将 Battleship / Submarine 受击细节列为下一轮首选；本轮继续沿用 v5 阶段，以一个范围有限、可由独立云端截图明确验收的海战视觉增量顺序递增。

## 背景

- 参考对象固定为百度百科 lemma id `4042982` 对应的 Noble Master Games《沙漠风暴 Desert Stormfront》，不是其他同名作品。参考其海战截图中清晰的舰种轮廓、紧贴目标的损伤信息和高对比水面交火语言；只借鉴可读性原则，不复制原素材或 UI。
- Battleship 已有分层舰体、双联装主炮、双发齐射、舰体闪光和主 / 副水柱；通用 `damageStateNode` 会在 62% / 35% HP 阈值显示烟、焦痕和火点，但战列舰仍与陆空单位共用同一组简单形状，缺少舰体破口、甲板焦痕和舷侧受损层次。
- Submarine 被 `configureDamageStateNode(...)` 和 `updateDamageStateVisual(...)` 明确排除，避免水面常驻烟火泄露隐身位置；被合法命中时只通过 `shouldShowAntiSubmarineHitFeedback(...)` 调用短暂的 `showAntiSubmarineHit(...)`，当前只有一个椭圆冲击环和 `ASW HIT` 文本。
- `fire(attacker:target:)` 是玩家与 AI 共用的直接战斗结算入口，已经统一处理 `canAttack`、已知目标、潜艇侦测、伤害和反馈。本轮不得另建平行伤害路径，也不得改变 `revealedUntil`、声呐或战争迷雾语义。

## 目标

1. 在既有实体视觉树内为 Battleship 预创建专属战损细节：沿甲板 / 舷侧布置一处不规则深色破口、短焦痕或撕裂线，并在 Critical 档增加紧凑的第二受损热点（小火芯 / 暗烟或发光裂口）。这些节点必须随 `damageStateNode`、实体镜像、移动、迷雾隐藏和销毁，不遮挡主炮、舰桥、生命条、旗标或 label。
2. 保持既有两档阈值：HP `<= 62%` 显示轻度 Battleship 甲板 / 舷侧破损与现有短烟；HP `<= 35%` 才显示更强热点、第三段烟与火点。修复到阈值以上时继续由 `updateHealthBar(...)` 隐藏，不新增第二套 HP 状态。
3. 扩充 `showAntiSubmarineHit(...)` 为紧凑的深水反潜命中组合：双层椭圆压力环、中心浅青水沫 / 小水柱、3-5 个确定性气泡或水滴，以及保留但不喧宾夺主的 `ASW HIT` 标签。普通效果约 0.6 秒内淡出并移除。
4. 只有 `shouldShowAntiSubmarineHitFeedback(...)` 已判定玩家 Submarine 或玩家已知敌方 Submarine 时才能创建新反潜效果；未知敌方潜艇不得通过压力环、气泡、小水柱、文字或任何常驻节点泄露位置。
5. 给 `showAntiSubmarineHit(...)` 增加仅供 capture 使用的 `persistent` 参数；普通真实战斗保持动画清理，只有 `DESERT_CI_CAPTURE_MODE=1` 且 marker 为本轮专用值时冻结视觉证据。
6. 新增 capture-only `naval-damage` coast 场景：同屏编排一艘约 29% HP 的 Blue Battleship 和一艘处于玩家合法已知状态、约 46% HP 的 Red Submarine；Blue Battleship 真实锁定 Submarine 并冻结 reload，显示 Battleship Critical 战损、Submarine 模型 / 生命条、反潜双压力环 / 水沫 / 气泡 / `ASW HIT`、舰炮射程圈、攻击意图与单选目标 HP / 距离 / reload。
7. GitHub Actions 从二十三次扩展为二十四次独立 simulator launch，新增 `simulator-naval-damage.png`；既有二十三张截图及其场景保持不变。

## 非目标

- 不改变 HP、damage、armor multiplier、range、cooldown、target acquisition、`canAttack`、AI、经济、生产、任务、胜负、移动或寻路。
- 不改变 Submarine 的 `revealedUntil` 时长、声呐覆盖 / 检测、已知目标判定、隐身恢复或节点隐藏语义；不给普通 Submarine 添加常驻水面烟火、油迹、航迹或战损节点。
- 不让新的双压力环、气泡或小水柱产生第二次伤害、范围伤害、持续伤害、击退或额外揭露。
- 不修改 Battleship / Submarine 基础模型、舰炮齐射、水面命中数值、HUD 动作数量或触控规则。
- 不新增外部依赖、纹理、图片、音频或随机粒子系统；不做无关重构。
- 不运行本地 Xcode build、本地 simulator 或本地玩法探针。

## 当前架构依据

- `GameEntity.damageStateNode`、`damageSmokeNodes`、`damageFireNode` 与 `damageScorchNode` 是非结构单位持续战损的实体自有节点；`configureDamageStateNode(...)` 只配置一次，`updateDamageStateVisual(...)` 由 `updateHealthBar(...)` 统一按 HP 阈值切换。
- 当前 Submarine 在上述两个 helper 中被明确排除；该保护必须保留。本轮 Submarine 只增强 `effectsLayer` 上短生命周期的合法命中反馈。
- `fire(attacker:target:)` 在实际扣血前计算 `showASWHit = shouldShowAntiSubmarineHitFeedback(for:)`，扣血后才调用 `showAntiSubmarineHit(...)`；此现有门槛应继续作为唯一普通玩法入口。
- `showAntiSubmarineHit(...)` 当前直接向 `effectsLayer` 添加压力环与标签；可在同一 helper 内组合水沫和气泡，并用统一 root 管理 zPosition、动画和清理。
- `prepareCICaptureScene()` 已按 `DESERT_CI_COMMAND_MARKER` 分流多个 capture-only 场景；新增场景必须在 land / air / 默认 coast 分支之前准确返回，普通 App 不设置 capture 环境变量时绝不进入。
- `.github/workflows/ci-results.yml` 当前清理、启动和 manifest 列表包含二十三张 PNG；新增截图必须同步三处，且继续逐次 launch、截图后 `kill -0` 检查。

## 风险与禁止项

- 风险：把反潜效果挂在独立 `effectsLayer` 会在潜艇重新隐藏后短暂留在世界中；普通 helper 只能在既有 `showASWHit` 合法门槛后创建，并必须快速清理，禁止改成常驻油迹或长烟柱。
- 风险：Battleship 的实体会通过 `xScale = -1` 镜像；专属破口与热点必须作为实体子节点并检查镜像后的挂点，不得漂离舰体。
- 风险：已有主炮、舰桥、旗标、生命条和 `damageStateNode` 层级较密；新增节点必须紧凑，不能以大面积不透明烟火遮住识别信息。
- 禁止删除 Submarine 在 `configureDamageStateNode(...)` / `updateDamageStateVisual(...)` 的排除条件。
- 禁止通过 ASW 命中效果写 `revealedUntil`、修改 sonar range 或调用绕过 `isKnownToFaction(...)` 的显示逻辑；capture-only 的合法可见编排不得进入普通启动。
- 禁止新增随机结果导致同一 capture 构图漂移；气泡 / 水滴位置应固定或由稳定实体 / 坐标值确定性产生。
- 禁止把一次视觉组合实现为多次 `fire`、多次伤害或多个战斗状态机。
- 禁止修改签名 Team ID、纳入 Unity 报告、提交构建产物、删除用户文件或进行无关格式化。
- 禁止使用旧 run、旧 artifact、旧截图或 Agent B 文字汇报冒充本轮云端验证。
