# v5.19 / 海空交战反馈层级

## 1. 版本与分配依据

- 版本号：`v5.19`。
- 分配依据：v5.18 实现 commit `6ae2c94ef77a5dc64afd9e7abaaee72e5bd7f812` 与日志 artifact 对应远端提交 `5872087f5d1ce3f1e9c74c47a96dbcdf2f07ae83` 已通过最新云端复核；v5.14-v5.18 已分别覆盖航母甲板停机位、潜艇接触 cue、海空选择面板、小地图海空微标和海岸线静态细节。本轮继续选择一个不改变玩法语义、能复用现有 24 张云端探针的海空战斗读图增量。
- 本轮唯一目标：修复并强化既有世界空间 `FOCUS` / `ATK` 海空交战标注的层级与可读性，尤其避免空军或大型海军实体遮挡共享集火环、目标环、血量段和橙色方向 cue。

## 2. 背景与当前架构依据

- `DesertFrontline/GameScene.swift` 是事实核心。`GameEntity` 的实体模型、选择子树、实体迷雾和生命周期已经存在；`effectsLayer` 承载世界反馈，现有 marker helper 负责一次性节点创建和 transient 清理。
- `refreshFocusFireMarker(for:)` 根据现有 `primaryCombatTarget` / `sharedFocusFireTarget` 和 `isKnownToFaction(..., observer: .player)` 只读确定合法目标，当前共享 FOCUS marker 使用固定 `zPosition = 240`。
- `showAttackTargetMarker(...)` 已有红色虚线目标环、橙色双 V cue 和 `ATK <short code>` 文案，使用现有 `presentCommandMarker(...)`，当前 marker 使用 `zPosition = 268`。
- 实体本身按 `zPosition(for:)`、域偏移、迷雾父节点和实体子树显示；空军与大型海军的模型高度可能高于旧的固定 FOCUS 层。不能通过绕开 `isKnownToFaction(...)`、把未知目标写入 HUD / 小地图或创建平行战斗系统来解决。
- 当前海空模型、航迹、命中反馈、耐久塔、武器就绪刻度、潜艇 `CONTACT` / `SONAR` / `STEALTH`、小地图朝向齿和海岸湿沙 / 礁石均已通过前轮验证，本轮必须保持这些链路不变。

## 3. 目标

1. 让合法玩家可见的海军 / 空军目标上，`FOCUS` 集火环、共享目标血量段、`ATK` 目标环和橙色方向 cue 在同一交战画面中稳定可读，不被目标实体主体或海空特效无意遮挡。
2. 复用现有 marker 节点和颜色语言；必要时集中定义有限的世界交战 marker z 序 / 层级 helper，避免在多个 helper 中继续散落 magic number。
3. 保留当前陆军、建筑、Carrier 甲板、Submarine cue、HUD、小地图、战争迷雾和命令 marker 的行为。改动应只影响渲染层级、有限的 label 偏移或 marker 内部顺序。
4. 保持重开 skirmish、目标死亡 / 清理、目标离开认知范围、选择变化和 attack / attack-move / STOP 后 marker 清理链路正确。

## 4. 非目标与禁止改变

- 不新增攻击、伤害、射程、冷却、命中、目标搜索、AI、生产、Carrier guard、潜艇声呐、任务、胜负、经济或移动规则。
- 不新增 `GameEntity` 战斗状态、目标状态、航向状态或外部依赖；不得把 marker 当作碰撞、寻路、命中测试或迷雾数据。
- 不把 FOCUS / ATK 文字或目标血量复制到 HUD、小地图或未知敌方实体；目标合法性必须继续经过现有 `isKnownToFaction(...)` / 存活 / 可攻击过滤。
- 不删除或重绘 v5.14-v5.18 已验收的模型、航迹、水柱、ASW HIT、水沫、海岸细节、耐久塔、武器刻度或海空小地图微标。
- 不做与本轮无关的 `GameScene.swift` 重构、格式化、API 迁移或文件拆分。

## 5. 实现步骤

1. 阅读并确认 `GameScene.swift` 中 `refreshFocusFireMarker(for:)`、`showAttackTargetMarker(...)`、`presentCommandMarker(...)`、`refreshCommandIntentVisuals(for:)`、`refreshSelection()`、`updateFog(force:dt:)`、实体 z 序计算和 marker 清理入口；先理解父节点关系，不凭截图猜测层级。
2. 以最小改动集中定义世界交战反馈层级，例如使用已有 `effectsLayer` / marker root 的相对 z 序或一个私有 helper。层级必须同时考虑：实体主体、实体子节点（耐久塔 / 武器刻度 / Carrier 甲板 / Submarine cue）、普通攻击 marker、FOCUS marker、HUD 和 fog layer。
3. 调整 `FOCUS` marker 的 root / 子节点顺序和必要的文字、血量段偏移，使空军目标上方的 `FOCUS n CODE NN%` 不落入机身；海军目标上的 label 不压住舰炮、舰岛、航迹或水面命中反馈。保持原有环形几何、颜色和短码，不新增大面积遮罩。
4. 调整 `ATK` marker 的 root / 子节点顺序或有限 label 定位，使红色虚线环与橙色双 V cue 位于目标外围、`ATK CODE` 不与 FOCUS 血量段重叠；若同一目标同时存在 FOCUS 与 ATK，必须使用确定性上下分带，而不是依赖创建时序。
5. 确认 marker 仍只在合法可见目标上显示：未知敌方、未侦测潜艇、迷雾外目标不得因提升 z 序而泄露；marker 的父节点仍受既有 fog / scene 生命周期控制。目标死亡、STOP、目标循环、重开和选择变化后不得残留旧 marker。
6. 代码中只保留必要的短注释，说明共享 marker z 序或 FOCUS / ATK 分带的原因；不要加入调试打印或临时探针分支。

## 9. 风险

- SpriteKit 的父节点 z 序、实体域偏移和 effects / fog 层级可能导致仅改一个 magic number 仍有遮挡；必须确认实际父节点和相对 z 序。
- marker 过高可能压住实体关键模型或泡沫 / 水柱，过低又会恢复空军遮挡；应使用确定性分带、有限 label 偏移和低透明填充。
- FOCUS 与 ATK 共存时可能文字互相覆盖；应优先分离文字带，不通过缩小到不可读来解决。
- fog / lifecycle 父节点错误会造成迷雾泄露或重开残留；所有节点必须沿用现有清理和可见性链路。
