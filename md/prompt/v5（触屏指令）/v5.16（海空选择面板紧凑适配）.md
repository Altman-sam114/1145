# v5.16 / 海空选择面板紧凑适配

## 版本号与版本分配依据

- 版本号：`v5.16`。
- 分配依据：当前 `main` 的 v5.15 日志提交为 `ebca437136491e65801962ff941d616c67ef9168`，实现与日志 artifact 均已验收。现有单选面板仍把 ASW、Sonar、Carrier 甲板/队列/翼队和护航摘要串成较长单行；继续 v5 触屏指令阶段，做一个只作用于 HUD 展示层的紧凑适配增量。
- 公开参考延续使用 Noble Master Games [Desert Stormfront press sheet](https://www.noblemaster.com/press/sheet.php?p=desert_stormfront)、[官方预告片](https://www.youtube.com/watch?v=7oZC6DpIUhQ)、[itch.io 页面](https://noblemaster.itch.io/desert-stormfront) 与 [IndieDB 截图页](https://www.indiedb.com/games/desert-stormfront/images/screenshots-for-desert-stormfront)：只借鉴小屏触控 RTS 将单位职责、目标和就绪状态分层放在固定面板的方向，不复制原作 UI、素材或文案。

## 背景

- `addSelectionInfoPanel(frame:compact:)` 创建固定宽度 tactical map 旁的四/五行单行 `SKLabelNode`；`updateSelectionInfoPanel(selected:)` 负责把 `selectionInfoContent(for:)` 的 rows 写入这些节点并按既有状态设置颜色。
- `singleSelectionInfo(for:)` 会把 `selectionCapabilityInfoLine(for:)`、`sonarInfoLine(for:)`、`carrierDeckQueueAndRallyLine(for:)`、`carrierAirWingLine(for:)`、护航、来袭和武器就绪摘要组合进同一行。Battleship、Carrier、Submarine、Fighter、Helicopter 的职责信息因此容易超出 210pt 面板的可读宽度。
- 所有这些文案目前只读既有实体状态，内容和颜色索引正确；本轮目标是保证单行不被裁切、保持触屏战斗时最重要的 HP / target / ready / incoming 信息优先可读，不重写玩法状态。

## 本轮目标

1. 在 `updateSelectionInfoPanel(selected:)` 的展示边界加入确定性的单行适配：
   - 记录面板行的可用宽度（面板宽度减左右内边距），每次刷新先恢复基准字号和 `xScale = 1`，再对超宽文本做有限、可预测的字号/水平缩放；不得让字体小到无法识别。
   - 适配只作用于选择面板行，不能改变标题、命令条、任务面板、小地图或实体世界文字。
   - 空行、pending 状态、颜色状态和目标血条继续沿用原逻辑。
2. 对海空高频长 token 做展示层短码压缩，同时保留足够的语义：
   - `ASW attack` -> `ASW`，`Sonar <range> Ctc <n>` -> `SON <range> C<n>`，`No sonar` -> `No SON`。
   - `Weapon ready` -> `Ready`，`Reload x.xs` -> `Rld x.xs`。
   - `Rally set/unset`、`Queue`、`Wing`、`Escort`、`Need`、`Operational`、`Attack-moving`、`Holding position` 等在面板行中使用稳定短码（如 `RLY+/-`、`Q`、`W`、`Esc`、`N`、`OP`、`AMOV`、`HOLD`）。
   - 不压缩单位 short code、HP 数值、目标类型、`Ctc` 数量、`Tgt`、`IN`/`INCOMING` 的事实含义；若某行不超宽，仍保持原可读文案或只做已定义的稳定 token 替换。
3. 保持海空信息优先级：自身 HP、目标 HP/距离、武器就绪/装填、来袭状态不能被隐藏或换行；Carrier 的 `Deck 3PAD H/J`、Rally/Queue、Wing/GW 组成与接触数继续存在；Submarine 的 `Stealth` / sonar contact / detect 状态继续存在。
4. 不新增按钮、滚动、分页、触摸命中区、实体状态、命令或第 25 张截图；复用现有 24 张云端探针。

## 非目标

- 不修改 `selectionInfoContent` 的状态判断、`selectionInfoRowColors` 的颜色索引、HP / target health bar、`primaryCombatTarget(...)`、`incomingThreatSummary(...)`、weapon timer、`canAttack(...)`、声呐、潜艇侦测、Carrier guard、生产、AI、战斗、经济、迷雾或胜负。
- 不改变实体模型、v5.15 潜艇细节、Carrier 甲板节点、地图地形、攻击/移动/停止/目标循环行为。
- 不新增外部依赖、图片、纹理、音频、随机动画、测试场景或 workflow launch；不修改 `.github/workflows/ci-results.yml`。
- 不把文本截断成省略号导致目标/状态丢失；不允许文字换行、重叠面板边界、覆盖小地图或压住目标血条。
- 不运行本地 Xcode build、本地 simulator、本地截图或本地玩法探针。

## 当前架构依据

- `selectionInfoRowLabels` 是面板预创建的行节点；`addSelectionInfoPanel(frame:compact:)` 已知道 compact 布局和行宽，本轮应在此保存基准字号/可用宽度。
- `updateSelectionInfoPanel(selected:)` 是唯一把 rows 写入 UI 的共享刷新入口；展示压缩和宽度 fitting 应集中在这里，不在 Carrier、Submarine、Battleship、Fighter 等玩法 helper 中各写一套 UI。
- `singleSelectionInfo(for:)`、`groupSelectionInfo(for:)` 和 pending 内容保持原始事实字符串，便于颜色、测试和未来逻辑复用；如需纯展示短码，应使用单独无状态 helper。
- `selectionInfoRowColors(for:)` 按固定行索引设置自身 HP、目标 HP、Weapon/Incoming 等颜色；行顺序和颜色不可改变。
- `updateSelectionTargetHealthBar(selected:)` 独立管理底部目标血条；新 fitting 不得改变其位置、比例、阈值或隐藏门槛。
