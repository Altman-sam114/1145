## 2. 背景与当前架构依据

- DesertFrontline/GameScene.swift 是当前事实核心。updateCombat(dt:) 负责战斗倒计时和目标合法性，fire(attacker:target:) 负责既有攻击状态流：伤害、耐久刷新、击杀、AI 防御、战争迷雾和胜负仍由原链路处理。
- fire(attacker:target:) 在攻击者为 battleship 或 coastalBattery、且攻击者对玩家可知时调用 showNavalGunSalvo(from:to:kind:faction:)；写入目标 HP 后，shouldShowNavalWaterImpact(...) 决定是否调用 showNavalSalvoImpact(target:faction:)。这两个 helper 是本轮海军炮击视觉的主要入口。
- effectsLayer 位于实体层之上、战争迷雾层之下。当前 showNavalGunSalvo(...) 已有双侧 lane、炮线 glow / core、移动中的 shell、炮口 flash、后飘 smoke，以及 Coastal Battery 的 showCoastalBatteryRecoil(...)；showNavalSalvoImpact(...) 已分派主 / 次水面 impact，并调用 showNavalHullStrike(...) 显示舰体闪光、核心、火花和烟雾。
- CI capture 在 .github/workflows/ci-results.yml 中复用 DESERT_CI_COMMAND_MARKER=naval-salvo、coastal-battery、carrier-strike 和 naval-damage 等既有启动，不应新增第 25 次 launch。capture-only 场景可以传递 persistent=true，普通运行使用短动画；两种模式都必须保持可读构图。
- 既有舰船模型、舰炮射程圈、舰船航迹、Carrier strike、潜艇声呐 / ASW HIT、战损耐久塔、目标 HP / 距离 / reload、HUD、小地图和 fog 认知边界均已验收。本轮只能叠加视觉反馈，不能改变这些事实来源。

## 3. 单一目标的具体范围

1. 在 showNavalGunSalvo(...) 内保持同一齐射的两个确定性 lane。炮口 flash / recoil、短烟、发射中的 shell 和轨迹要有稳定左右分离，不因目标方向或阵营镜像而重合、翻转错误或落到不可读位置。
2. 在 showNavalSalvoImpact(...) 及其现有 impact helper 内强化“主落点 + 次落点 + 舰体命中”的关系。主水柱、次水柱和 showNavalHullStrike(...) 要保持有限错位及清晰层级；不得产生覆盖整艘舰体的大面积白块。
3. 普通动态运行中可以使用很短、确定性的错列 / fade / scale 过渡，使双炮齐射有轻微先后节奏。该过渡只能作用于 SpriteKit 特效节点，不能延迟 target.hp 写入、攻击冷却、attackTimer、目标选择或任何游戏状态。
4. persistent=true 的 CI 冻结画面必须一次呈现完整的双炮线、炮弹、炮口 / 烟雾与命中反馈，不依赖截图时机才能看到关键节点；普通短动画结束后必须沿用现有 removeFromParent 生命周期清理。
5. 保持当前颜色语言：玩家海军沿用青蓝 / 白色，敌方沿用橙红 / 白色，水面反馈沿用浅青 / 白色。只允许做局部透明度、线宽、尺寸、偏移或时序调整，不引入新配色体系。

## 5. 实现步骤

1. 开始实现前先阅读 AGENTS.md、update_log.md、md/flow/flow.md、md/flow/flowchart.md、md/test/test.md、README.md、v5.20 提示词和本文件；再精确阅读 fire(...)、showNavalGunSalvo(...)、showNavalSalvoImpact(...)、showNavalWaterImpact(...)、showNavalHullStrike(...)、showCoastalBatteryRecoil(...) 及 CI capture 调用点。先确认父节点、z 序、persistent 语义和可见性 guard，再编辑。
2. 在 showNavalGunSalvo(...) 内以最小改动保持两条 lane 的确定性几何。可以集中定义局部 lane 数据或短 helper，统一保存 lane offset、muzzle、impact 和角度；不得把这些视觉位置写回实体坐标、目标坐标或战斗状态。
3. 只在普通短动画模式增加有限的错列节奏，例如给第二条 lane 使用极短的确定性等待，或让两枚 shell / flash / smoke 的 fade 和进度略有差别。若使用 SKAction.wait，persistent 模式必须直接创建完整静态节点；普通动画总时长应短于现有截图等待窗口。不得在 fire(...) 外包裹延时。
4. 在 showNavalSalvoImpact(...) 中保留现有主点 / 次点的 footprint 相对偏移和可见性边界，只调整水柱、波纹、舰体 flash / spark / smoke 的有限顺序、透明度、尺寸、错列或短动画。优先复用 showNavalWaterImpact(...) 和 showNavalHullStrike(...)，不要复制第三套命中特效。
5. 检查节点层级：炮线和 shell 应高于一般实体但不遮住 HUD / fog；炮口烟雾可低于炮线；水柱与舰体命中应同时可见。若调整 z 序，只保留必要的局部常量或短注释说明原因；所有节点仍挂在 effectsLayer 或其现有特效根节点。
6. 保持两类入口一致：Battleship 与 Coastal Battery 都要有双 lane 可读反馈；Coastal Battery 继续保留既有 recoil / 岸边尘浪。Carrier 对海 strike、Fighter / Helicopter strike、Artillery 对海、Submarine / ASW 链路不得被本轮重写。
7. 检查目标不可见、攻击者不可知、目标死亡、STOP / 重开和普通节点清理路径。效果只在既有 fire(...) 可见性条件下产生；不新增常驻节点；重复齐射不得无限累积未清理特效。
8. 实现后只对本轮相关 diff 做静态检查，确认 Swift 语法括号、persistent 分支、z 序和节点移除路径没有明显错误，再同步真实文档。

## 10. 风险与处理

- 现有炮线、shell 和 impact 分属 effectsLayer 的不同 z 序；只改一个 z 值可能导致炮线压住舰体、烟雾盖住命中或水柱低于实体。实现前必须看完整父子节点关系，并用局部、可解释的层级调整。
- fire(...) 先写 HP 再调用 impact；若把等待放进战斗函数或用异步 closure 改写调用顺序，会误改变游戏语义。所有延迟只能在普通特效节点内，persistent 直接静态呈现。
- CI 固定截图等待时间有限；普通动画过长会让 naval-salvo / coastal-battery 截到空场，动画过短又无法辨认层次。保持总时长短且 deterministic，并为 persistent capture 提供完整快照。
- showNavalSalvoImpact(...) 同时服务 Battleship 和 Coastal Battery 对舰命中；调整目标相对偏移时必须保持 footprint-aware、阵营镜像和海岸可见性，不得硬编码只适用于一张截图的世界坐标。
- effects 节点频繁创建可能造成残留或性能回归；重复齐射必须沿用现有 removeFromParent() 清理，禁止添加常驻定时器或无限动作。
