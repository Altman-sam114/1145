# v5.20 / 任务目标进度带与阶段可读性

## 1. 版本与分配依据

- 版本号：`v5.20`。
- 分配依据：v5.19 已完成并通过对应 `origin/main` 云端 artifact 验收；本轮继续推进触屏 HUD 的信息层级，只做一个不改变玩法规则的任务面板增量。
- 本轮唯一目标：在现有任务面板内增加紧凑的阶段进度带，让已完成、当前和未开始任务阶段可以在第一视野内快速区分。

## 2. 背景与当前架构依据

- `DesertFrontline/GameScene.swift` 是当前事实核心。`MissionStage.allCases` 定义固定任务顺序，`completedMissionStages` 保存已完成阶段，`activeMissionStage()` 返回第一个未完成阶段，`missionDetail(for:)` 是当前阶段详情的事实来源。
- 任务面板在 `layoutHUD()` 创建，标题和详情在 `updateHUD()` 通过 `missionStatusContent()` 刷新。重开 skirmish 在 `restartSkirmish()` 清空 `completedMissionStages`，不得新增平行任务状态。
- 当前云端探针已有 24 张 PNG，任务面板属于 HUD 视觉层；本轮应保持既有颜色语言、紧凑尺寸和移动端布局约束，不新增素材或外部依赖。

## 3. 目标

1. 在现有 mission panel 内增加 6 阶段的紧凑进度点或分隔线。
2. 已完成阶段使用明确的绿色/青绿色状态，当前阶段使用金色或亮色强调，未开始阶段使用低透明度中性色。
3. 每次 `updateHUD()` 都根据 `completedMissionStages` 与 `activeMissionStage()` 刷新进度带；任务完成、胜负和 `SKRM` 重开后不得残留旧状态。
4. 保留现有标题、`missionDetail(for:)` 详情、奖励、任务顺序、战争迷雾、HQ 认知边界和所有命令交互。
5. 保证 compact HUD 和标准 HUD 下进度带不压住标题/详情，不溢出面板，不引入依赖动态文字长度的布局漂移。

## 4. 非目标

- 不改变 `MissionStage` 的数量、顺序、完成条件、奖励或 `completedMissionStages` 的生命周期。
- 不新增任务状态字段、玩家操作按钮、世界目标标记、地图信息泄漏、AI 逻辑、战斗/经济/迷雾逻辑或素材。
- 不重构 `GameScene.swift`，不把任务系统拆出平行模块，不调整 v5.19 海空交战反馈。
- 不默认运行本地 Xcode build、模拟器或 `simctl`。

## 5. 实现步骤

1. 在 HUD 属性中增加最小的进度点/连接线节点集合，生命周期与既有 mission panel 一致。
2. 在 `layoutHUD()` 创建并定位固定数量的节点，使用面板内部稳定坐标；compact HUD 使用相同数量但更紧凑的几何尺寸。
3. 在 `updateHUD()` 或清晰的局部 helper 中依据 `MissionStage.allCases` 更新节点颜色、alpha 和必要的当前阶段强调；不要从详情文本反解析状态。
4. 确认胜利/失败、阶段完成和 `restartSkirmish()` 后刷新路径会更新进度带。
5. 同步 README 当前功能事实、`md/flow/flow.md` 的 HUD/任务数据流，必要时同步 `md/flow/flowchart.md`；本轮测试规范如无变化可只核对，不虚构新测试。

## 7. 测试与云端交付要求

- 开始前确认：`git fetch origin`、`git switch main`、`git pull --ff-only origin main`，并确认工作树只有已知用户改动 `DesertFrontline.xcodeproj/project.pbxproj` 和 `md/unity分析/`；不要暂存、覆盖或删除它们。
- 本地只运行轻量检查：`git diff --check`，并可运行与本轮相关的静态文本/括号检查；禁止本地完整 Xcode build、模拟器和 `simctl`。
- Agent B 必须只提交本轮相关文件，commit subject 使用 `v5.20: ...`，确认分支为 `main` 后 `git push origin main`。
- GitHub Actions 必须对该 commit 生成 generic iOS device build、静态检查、project lint 和现有 simulator probe 结果，并上传未加密结果包，至少包含 `ci-artifact-manifest.json`、`junit.xml`、`xcodebuild.log`、`ci-failure-summary.md` 与项目专属结果文件及 24 张 PNG。
- Agent C 必须以准确的 `origin/main` commit 查找最新 run，下载到 `/private/tmp/desert-frontline-c-review-<run_id>/`，核对 manifest 的 branch、commit SHA、run ID/attempt、JUnit、build log、failure summary、项目结果文件、24 张 PNG 和 ZIP 完整性；不得使用旧 artifact 或本地输出代替。
- 云端失败时不得宣布本轮成功；由 Agent B 在 `main` 上追加修复 commit 后重新 push，或明确暂停原因。

## 8. 验收标准

- 代码中存在固定数量、可复用的任务阶段进度节点，并在布局时创建、在 HUD 刷新时更新。
- 当前阶段、已完成阶段、未开始阶段在云端截图/结果或静态证据中有稳定的层级区别；不遮挡现有任务标题和详情。
- 任务完成顺序、奖励、胜负、迷雾边界、重开重置和 v5.19 海空视觉反馈保持不变。
- `README.md` 与 `md/flow/flow.md` 只描述已实现行为；不夸大为新的任务规则。
- 准确 commit 对应的 GitHub Actions generic iOS device build 与项目探针通过，Agent C 已下载并核对未加密 artifact。

## 9. 风险与禁止项

- 禁止把 `completedMissionStages` 之外的缓存当成任务事实来源，避免重开或阶段推进后不同步。
- 禁止将未完成的阶段写入 README 的完成能力，禁止泄漏未被玩家发现的 HQ/敌军信息。
- 禁止大范围格式化或无关重构，禁止新增外部依赖/素材。
- 保留用户未提交的 Team ID 与 `md/unity分析/` 改动；禁止 reset、checkout 覆盖或删除它们。
