## 背景与本轮目标

`GameScene.drawMap()` 清理并重建 `mapNode`、地形菱形、`addTerrainDetail(...)`、场景物件和独立 `fogLayer`。当前水侧已经通过 `shorelineSegments(for:)` 绘制浅水层、冲洗带、泡沫线和确定性泡点；开阔水面有波纹，沙地、油田和 Ridge 有各自静态细节。陆地侧仍缺少低对比度湿沙边缘，Ridge 与水相邻处也缺少少量礁石轮廓。

1. 为与水格正交相邻的 `.sand` / `.oil` 陆地 tile 增加确定性的湿沙唇。边缘沿现有等距四方向 edge table，位于当前陆地 tile 内侧，不跨 tile、不覆盖道路主体；可由低对比暗湿边和稀疏短高光组成，不能使用粗重白线。
2. 为与水格正交相邻的 `.ridge` tile 增加稀疏暗色礁石边缘。沿现有 Ridge 岩体、阴影和碎石风格绘制短轮廓或少量碎片，不形成连续黑带，不遮挡舰体、岸防炮、弹道或海岸泡沫。
3. 复用 `shorelineSegments(for:)` 的四方向映射：`row - 1` top->right、`col + 1` right->bottom、`row + 1` bottom->left、`col - 1` left->top。可添加最小无状态 helper，但不得另写方向表。
4. 所有变化使用 `terrainDetailHash(for:)`，相同 `skirmishSeed` 稳定、不同 seed 仅有限变化。新节点只挂 `mapNode`，由既有 fog 覆盖和 `drawMap()` / `SKRM` 重建清理。
5. 保留水侧浅水、wash、foam、bubble、开阔水波纹、道路、沙丘、油污、Ridge 岩体、场景物件和现有 HUD/小地图；复用既有 24 张 cloud probe，不新增 launch。

## 当前架构依据

- `drawMap()` 先创建基础 terrain diamond，再调用 `addTerrainDetail(...)` 和 `addScenery(...)`，最后建立独立 fog node；地图视觉不在 `update(_:)` 中逐帧创建。
- `addTerrainDetail(...)` 的 `.water` 分支调用 `shorelineSegments(for:)`；`.road` 使用 `roadConnectionPoints(for:)`；`.oil` 使用污渍/渗流圈/裂纹；`.ridge` 使用岩体/阴影/亮面/碎石；`.sand` 使用沙丘/风纹/灌木。
- `shorelineSegments(for:)` 输入必须是水格，使用四个正交邻格并返回水格局部坐标 `(start,end)`；扩展时保持现有水侧调用语义和边方向。
- `terrainDetailHash(for:)` 只由 tile 坐标和 `skirmishSeed` 生成；新增细节不得依赖实体 id、时间或每帧状态。
- 新节点使用当前 `zPosition(for:)` 附近的地图细节层，位于地表上、实体/战斗效果/HUD 下；不得进入 `entityLayer`、`effectsLayer`、fogLayer、实体子树、小地图或 HUD。

## 验收标准、风险与禁止项

- 湿沙唇只出现在水相邻 `.sand` / `.oil`；礁石只出现在水相邻 `.ridge`；`.road` 不新增陆地侧装饰。
- 水侧现有层次保留；方向映射与 `shorelineSegments` 一致；线段不越出 tile、不形成跨 tile 接缝；节点只挂 `mapNode` 并由 fog 覆盖；重建无残留；同 seed 确定性；节点密度有限。
- 不出现新增玩法状态、碰撞、路径、AI、战斗、生产、经济、迷雾或触控行为；README/flow/flowchart/test 只描述真实静态视觉事实。
- 风险：等距边方向易反转；湿沙过亮会和泡沫混淆、过暗会像道路/障碍；礁石过密会压低舰体/炮迹对比；油田中心污环可能与边缘混淆；错误父节点会绕过 fog；每帧节点和动画会增加性能风险。
- 禁止 `git reset --hard`、`git checkout --`、非 main 分支、PR/develop/smalldata_test/codeb 流、修改 workflow、外部素材、伪造 artifact、提前修改 `update_log.md`。
